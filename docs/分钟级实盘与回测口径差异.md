# 分钟级实盘与回测口径差异

> 适用：子策略周期为日线以下（`1m / 5m / 15m / 30m / 1h`）时。
> 结论：**回测结果不能按收益/回撤线性外推到实盘**。实盘成交率更低、成交均价更差、bar 更稀疏。
> 完整取证与实测数据见 [分钟级回测实盘一致性与信号源核查](plans/2026-11-19-分钟级回测实盘一致性与信号源核查.md)、
> [TQ 1m 接口实测](plans/2026-11-20-TQ-1m接口实测.md)。

## 1. 数据源：默认快照合成，可选原生同源

| 端 | 1m bar 来源 | 说明 |
|---|---|---|
| 回测 | TQ 历史 1 分钟线 | 直接读本地 `vipdoc/*\minline\*.lc1`，原生不重采样 |
| 实盘（默认，`live.native_minute.enabled=false`） | 行情快照合成 | 约 5–30s 采样、60s 主循环发布，只发布已完成 bar；覆盖 tdx/ths/alert/goldminer |
| 实盘（`live.native_minute.enabled=true`） | 本地原生 `.lc1` / `.lc5` | 1m 读 `.lc1`、5m 读 `.lc5`、15m/30m/1h 走原生周期（TDX 由 `.lc1` 聚合），与回测同源；只取标签 ≤ 当前墙钟的已闭合 bar，判新只看标签前进 |
| 实盘（iquant） | 掘金桥 K 线轮询 | 不经过快照合成 |

原生源依赖外部「TDX数据工具.exe」持续写入 `D:\zd_zyb` 且清单（如 `CCJX.blk`）已更新
（实测 15–30s 一轮，池内全覆盖）。超过 `live.native_minute.stall_timeout_seconds`（默认 180s）
不前进 → 自动回落快照合成，WARNING + risk 事件留痕（含最后前进时刻与滞后秒数）；恢复前进自动切回。

原生源的午休边界与快照不同（2026-11-20 实测 600211.SH 的 `.lc1`/`.lc5`）：1m 上午
09:31–11:29（119 根）、下午 13:01–15:00（120 根），全天 **239 根，没有 11:30 根**；5m 上午止于
11:25、15m 止于 11:15、30m 止于 11:00、1h 止于 10:30，同样**没有 11:30 桶**。这是通达信原生
形态（每半场根数不对称），不是缺数据；源内真实缺失只有「下载工具停写/漏写某一分钟」这一类。
（13:00 只是分钟桶锚点、不是 bar 标签，下午首根实测为 13:01。）
（当日 1m 成交量合计比日线少 4,600 股，约一根分钟量级，与该分钟无 bar 吻合。）

`refresh_kline(type=17, '1m')` 只刷新客户端内存缓存，不下载、不补缺；TQ 的 1m 输出与本地
`.lc1` 逐值一致（OHLC 相同、Volume 相同、Amount = 文件值 ÷ 10000）。因此「TQ 盘中能否取到 1m」
等价于「本地 `.lc1` 是否在盘中更新」。

## 2. 快照合成 bar 的限制（默认路径 / 原生源回落时）

> 开启原生源且数据正常前进时，以下采样类限制不适用；原生路径改用 TDX 写入的完整分钟桶。

- **时间戳**：标签为分钟终点（10:50 分钟 → 10:51:00），与 TDX 1m 一致。
- **缺口**：取数失败或采样停摆会让整分钟无 bar，恢复后不回补；日志 `[bar-gap] … action=unrecoverable`。
- **半根 bar**：恢复后的第一根可能只有十几秒数据，但仍按完整 1m 发布。
- **OHLC**：open/close 为分钟内首/末采样价，high/low 为采样极值，可能漏掉采样间尖峰。
- **成交量**：快照日累计 `Volume` 差分，跨分钟边界时相邻 bar 的量会串位（总量一致、单根分布不同）。
- **多分钟周期**：只输出完整桶（桶内 1m 数量达标且逐分钟连续），缺一分钟整桶丢弃。
- **原生路径的缺口**：下载工具停写/漏写某一分钟 → 该 1m bar 缺失；多分钟周期缺一分钟整桶丢弃。
  回落是全局切换（整轮回快照合成），不会对单个缺口做插值补齐。**11:30 不算缺口**（见 §1）：
  原生 1m 上午止于 11:29、下午 13:01 起（13:00 为桶锚点，不是 bar 标签），原生 5m/15m/30m/1h
  也没有 11:30 桶；而快照合成会在 11:30 产出一根 1m bar，聚合后多分钟周期也多一个 11:30 桶
  （13:00 首轮补派）。两条路径每天相差一根，属形态差异，不是丢数据。

## 3. 信号与成交

| 环节 | 回测 | 实盘 |
|---|---|---|
| 信号产生 | bar 收盘 | 同左（已完成 bar） |
| 下单时点 | 下一根 bar 开盘 | 信号 bar 收盘后，受 60s 主循环轮询与（默认路径）快照发布延迟 |
| 成交价 | 下一根 bar 的 `Open`，必成交 | 信号 bar 收盘价挂限价 |
| 追价 | — | 默认**不追价**；开启后 ±1 tick，180s 超时撤单重挂 |
| 未成交 | 不存在的状态 | 离线统计约 **7.2% 买单 / 7.9% 卖单**下一分钟内信号价无成交 |

原生源只改变 bar 来源，不改变下单/成交模型：下单时点仍受 60s 轮询约束，成交价仍为信号 bar
收盘价挂限价、默认不追价。

价格噪声实测（2,856 个分钟对）：`|next_open − prev_close|/close` 中位 0.0125%、p90 0.0824%；
下一分钟不追价时买单无成交 7.2%、卖单无成交 7.9%。成交均价因此系统性劣于回测。

## 4. 回测绑定 ≠ 参数继承

实盘会话的 `backtest_record_id` 只是绑定关系，启动时按**当前**组合/策略行重建。以下字段
**不会被继承**，也不会进入漂移比较：

- 策略与子策略（`strategies`）
- 周期（`period`）
- 风控执行时点（`risk_timing`）——分钟 bar 的 `signal_bar_date=None`，实盘的「次日执行」分支不生效
- 追价开关/档数（`requote_enabled` / `requote_max_attempts`）
- 单笔金额上限（`max_order_amount`）
- 复权口径（回测取前/后复权，实盘必然除权价）

参数漂移检查只比较组合级执行/成本字段（`PARAMS_SNAPSHOT_FIELDS`），不覆盖以上项。
另有一套**拼盘绑定**（`pairing_service`）：它把策略/周期/`risk_timing`/追价/单笔上限冻结进
`binding_json`，当前策略行与冻结值不一致时配对失效。这是**校验**，不是继承——实盘始终按当前
策略行运行。

## 5. 何时会系统性偏离

| 情形 | 偏离方向 |
|---|---|
| 快照采样缺失/取数失败（默认路径） | 实盘漏信号（回测有该 bar） |
| 下载工具停写/漏写某一分钟（原生路径） | 该 1m 缺失；多分钟周期缺一分钟整桶丢弃（11:30 缺根不属此列，见 §1） |
| 信号价限价、默认不追价 | 实盘欠成交，持仓与收益低于回测 |
| 恢复后半根 bar（默认路径） | 极值与量失真，可能误触发或漏触发 |
| 成交量串位（默认路径） | 按 bar 量的下单闸/拆单笔数偏差 |
| 复权口径不同 | 除权日前后价格与信号偏离 |

## 6. 待定项（会改变产品行为，未实施）

1. **周期上限收敛**：是否限制分钟策略最短周期（如仅支持 5m 及以上），避免 1m 实盘不可用。
2. **触发口径改为快照价差**：是否把分钟信号触发从「1m bar 收盘」改为「快照价格变动」，以降低对合成 bar 完整性的依赖。
3. **TQ 1m 主备切换**：已落地为可选开关 `live.native_minute`（默认关闭）。盘中验证 TQ 1m 可实时更新后，开启即 1m 读 `.lc1`、5m 读 `.lc5`、15m/30m/1h 走原生周期；数据停止前进自动回落快照合成并留痕。

## 7. 分钟策略能否「盘中实时风控 / 实时下单」（2026-11-20 核验）

结论：**都能，粒度 = 策略自身周期**。1m 策略每分钟、5m 策略每 5 分钟评估一次风控与信号；
信号 bar 收盘后在同一轮行情轮询内提交限价单，不排队等到次日。

1) **实时下单**：1m bar 到达 → `LiveEngine._on_bar` 逐组合调 `_handle_bar`，后者在
   [live_engine.py:8705](file:///d:/project/tq-iquant-web/main/core/engine/live_engine.py#L8705)
   调 `portfolio.on_bar(period=bar.period)` 取信号，同一调用栈内到
   [live_engine.py:8748](file:///d:/project/tq-iquant-web/main/core/engine/live_engine.py#L8748)
   `_submit_one_order` 提交（无「攒到收盘」队列）。委托价默认 = 信号 bar 收盘价
   （[portfolio.py:63](file:///d:/project/tq-iquant-web/main/core/engine/portfolio.py#L63)）；
   `requote_enabled` 默认 False（不追价、不让价），开启后提交时先让 1 跳
   （[live_engine.py:6758](file:///d:/project/tq-iquant-web/main/core/engine/live_engine.py#L6758)），
   仍未成交按 `tq_trade.cancel_unfilled_minutes`（默认 3 分钟 = 180s，
   [config.py:307](file:///d:/project/tq-iquant-web/main/core/config.py#L307)）撤单并按
   `requote_max_attempts` 重挂。实际提交仍受 60s 主循环节拍与通道回填延迟约束。
2) **实时风控**：`portfolio.on_bar` 每根 bar 调 `_check_risks`
   （[portfolio.py:718](file:///d:/project/tq-iquant-web/main/core/engine/portfolio.py#L718)），
   止损/止盈/移动止损一律用 `bar.stocks[code].close` 判定并刷新持仓峰值。**策略自身周期**的
   bar 恒评估（5m 策略每根 5m bar 都评估）；**错周期** bar（1m bar 驱动 5m/1d 策略）默认只更新
   价格快照、不评估（[portfolio.py:556](file:///d:/project/tq-iquant-web/main/core/engine/portfolio.py#L556)），
   会话三态 `live_sessions.intraday_mismatched_risk_enabled` 打开后才逐 1m bar 评估。
   实际值：会话 1 为 **NULL（未显式设置）**，按会话内子策略周期自动推导——现存策略是
   1d，故生效值＝关；`config.yaml` 的 `tq_trade.intraday_mismatched_risk_enabled` 不再参与
   NULL 会话判定。含分钟策略的 NULL 会话，界面会提示确认一次并落库为显式值（显式值永远优先）。
3) **risk_timing 与实时性**：`next_day` 的实现是「`signal_bar_date` 非空则延期」，而分钟 bar 的
   `_signal_bar_date_for` 返回 None
   （[portfolio.py:42](file:///d:/project/tq-iquant-web/main/core/engine/portfolio.py#L42)），所以
   `next_day` 对分钟 bar 不生效；`immediate` 跳过的正是同一道 `_should_defer_order` 闸门
   （[live_engine.py:9897](file:///d:/project/tq-iquant-web/main/core/engine/live_engine.py#L9897)），
   对分钟 bar 本来就是空操作。跳过后仍受：交易时段/午休闸（11:30–13:00 不报，
   [calendar.py:465](file:///d:/project/tq-iquant-web/main/core/engine/live/calendar.py#L465)）、
   15:00 后转 deferred、执行模式（alert 不下单 / approval 需人工 / auto 直接报）、涨跌停夹价、
   成交量闸、单笔上限、资金分配、T+1、同向在途去重、`sell_scope`。
4) **前置条件一句话**：实时风控 = 会话在跑 + 该周期 bar 正常闭合（原生源需下载工具持续写盘，
   快照源需采样不停摆），要更细的跨周期粒度再开会话三态开关；实时下单 = 上述条件 +
   `execution_mode=auto`（或人工放行）+ 通道在线 + 交易时段内（午休/收盘后不报）。

口径澄清：§4 说的是「绑定回测记录不继承 risk_timing」，不是「分钟策略没有实时风控」。
界面《实盘配置指南》里「错周期风控」（LiveSessions.vue 三态下拉与指南第三节）表述与本条一致，
无冲突，无需改措辞。
