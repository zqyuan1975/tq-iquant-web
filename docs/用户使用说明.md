> 版本：封装版（`main/dist/tq-iquant`）／源码版（前端 `web/`，后端 `main/`，Python 3.13 + Vue 3 + FastAPI）

## 一、首次启动

**封装版（推荐给不使用 TQ 修改开发的用户）**

1. 运行安装包（`dist/installer/创懿基金量化投资平台-<版本>-<时间>-安装程序.exe`）。安装向导「附加任务」默认勾选：
   - 创建桌面快捷方式；
   - **登录后自动启动并保持运行（内建自愈守护，推荐）**——安装器注册登录计划任务
     `TQ-IQuant-Supervisor`，登录时执行 `"<安装目录>\tq-iquant.exe" --supervise`。
2. 双击桌面快捷方式打开界面（默认单进程，行为与以前一致）。若自愈后端已在运行，程序
   只打开界面复用该实例，不会再起第二个后端。
3. 首次启动自动创建 `data/`（SQLite）并执行数据库迁移（Alembic）。端口动态分配
   （8888~8898，占用则顺延），实际端口写在 `data/runtime/server.json`，不需要记端口。
4. 退出：关闭界面窗口即可（单进程模式随窗口退出）；**自愈模式（`--supervise`）不随
   窗口退出**。需要彻底停止时，先禁用计划任务
   `schtasks /Change /TN "TQ-IQuant-Supervisor" /DISABLE`，再在任务管理器结束
   `tq-iquant.exe`（监督进程与后端子进程各一个）。

**自愈与日志（两层保护，职责不重叠）**

- 进程内引擎看门狗（30 秒扫描）：只检测通道停摆 / 轮次卡住并告警（日志 + SSE +
  工作台决策流），**不重启进程**（它随进程一起消失）。
- 自愈父进程（`--supervise`）：每 10 秒探活 `/health`（版本/运行时长/端口/pid），
  子进程退出或连续 3 次无响应则退避重启；连续 5 次失败停止重试并写明确日志。
  父进程被杀后，子进程 5 秒内自行退出，不留孤儿占用端口。
- 日志：`logs/supervisor.log`（父进程）、`logs/supervisor-child.log`（子进程输出）、
  `logs/core.log`（应用）。安装目录不可写时回落到 `%LOCALAPPDATA%\创懿基金量化投资平台\`。
- **不要用 Windows 服务托管**：服务跑在会话 0、没有交互桌面，通达信/同花顺的键鼠
  自动化会失效。安装器只用「登录时计划任务」。

**源码版（开发模式）**

```bash
# 后端（main 目录）
uv run uvicorn core.main:app --reload        # http://127.0.0.1:8000

# 前端（web 目录，另开终端）
npm install
npm run dev                                    # Vite dev server，/api 代理到 8000

# 自愈模式（源码版同一条路径；子进程用 --serve 由父进程拉起）
python -m core.supervisor                      # 等价于 desktop.py --supervise
```

前置依赖：通达信客户端（行情/日线数据来源，回测必装；实盘 tdx 引擎与预警模式也依赖它）。实盘另按所选引擎准备对应客户端：通达信 TQ（同一客户端）、同花顺独立交易客户端 `xiadan.exe`、掘金终端（内含 `goldminer_bridge.py` 桥策略）、QMT 通道客户端（内含 `iquant_bridge.py` 生产桥；`iquant_bridge_live.py` 为未启用的信用腿）。

> 前端改动需 `npm run build` 重建 `web/dist` 才生效（FastAPI 直接托管 dist，无需重启后端）。

## 四、股票池

> 通达信规范股票代码统一带后缀：`000001.SZ` / `600000.SH` / `002415.SZ`。

- **左侧「通达信库」**：读取通达信客户端已存在的股票池列表；可查看池内股票。
- **右侧「本地库」**：导入回的池子（含同步来源代码映射）。
- 操作按钮（按状态显示）：
  - `查看` — 展开池内股票列表（仅在通达信端存在时显示）。
  - `同步` — 将通达信端最新池内容同步到本地（两端始终显示同一文案；本地列表加载失败不阻塞通达信列表）。
  - `删除` — 在本地删除该池（依赖本地映射，删除后再导入会新建）。
- 用途：回测时组合策略选择某一股票池，作为选股范围。

## 五、公式管理

> 公式 = 通达信技术指标公式。平台在**回测引擎内嵌入通达信 TQ 模块直接调用公式计算**，因此信号与客户端一致。

- **列表**：从通达信加载可用公式；`user_only=true` 可过滤只看用户公式。
- **导入**：把选择的通达信公式（get/read 类，含所需输出）导入平台，供组合策略子策略使用。
- 支持按 `ac_code`/`公式类型` 查看公式详情（`GET /formulas/tdx-info`）。
- 导入后在「组合策略」的策略公式字段中直接引用 `公式名`，配合买入/卖出/加减仓信号名使用。

**✳ 公式信号取值契约（务必遵守）**

平台判定信号是**精确相等匹配**：`公式输出值 == 配置的触发值(trigger_value)`，相等才触发，不按阈值区间判断。

1. 公式必须有与「信号名」**同名**的输出行（如输出 `买入` / `卖出` / `加仓` / `减仓`，名字随意，但必须与配置中的 `signal_name` 完全一致）。
2. **买卖取值约定**：买入输出 `1` 或 `2`；卖出输出 `-1` 或 `-2`。`0` 表示「未触发」的常态值，平台**禁止**将其配置为触发值。
3. `trigger_value` 仅允许 `{-2, -1, 1, 2}`，配置/导入时平台校验，其他值返回 HTTP 400（见 `core/api/formulas.py` `VALID_TRIGGER_VALUES`）。
4. 每个信号对应一行配置（信号名 + 信号类型 + 触发值），同一公式可含多个信号输出。典型配对：

| 信号类型 | 含义 | 触发值 |
|---|---|---|
| `OPEN` | 开仓 | 1（或 2） |
| `ADD` | 加仓 | 2（或 1） |
| `REDUCE` | 减仓 | -2（或 -1） |
| `CLOSE` | 清仓 | -1（或 -2） |

5. 提交回测时平台会校验：信号名必须在所选公式输出中**存在**、且触发值与配置一致，否则拒绝该回测（报错提示「信号不存在」/「触发值不匹配」）。

## 六、组合策略

> 组合策略 = **一个组合（Portfolio）** + 组合下的**多个子策略（Strategy）**。组合定全局资金/费用/熔断参数；子策略定选股公式、周期、资金占用与个票风控/加仓。资金按「持仓上限」分配（非预分），多策略上限之和可超 100%。

### 组合（Portfolio）参数

| 字段 | 说明 | 默认 |
|---|---|---|
| 名称 | 组合名称（非空） | — |
| 股票池 | 组合级选股池（**必选**）；子策略未设独立池时继承它 | — |
| 基准指数 | 绩效对比基准（通达信代码） | `000300.SH` |
| 初始资金 | 回测/实盘模拟起始资金（元） | 500,000 |
| 最大回撤 | 全局回撤熔断线 (0,1)：回撤超过 → 暂停新开仓，次日恢复；**累计触发 3 次后转手动恢复** | 20% |
| 日亏损限额 | 当日亏损限额 (0,1)：当日超过 → **当日暂停**新开仓，次日恢复 | 5% |
| 持仓上限 | 组合最大同时持仓数 | 10 |
| 最低佣金 | 单笔最低佣金（元，不足按此收取） | 5 元 |
| 买佣金率 | 买入佣金费率 | 0.025% |
| 卖佣金率 | 卖出佣金费率 | 0.025% |
| 印花税率 | 卖出时征收 | 0.05% |
| 过户费率 | 买卖双向按成交额计收（A 股现行 0.001%） | 0.001% |
| 滑点 | 成交滑点（按成交价比例） | 0 |
| 交易时段 | `full` 全时段 / `am` 仅上午 / `pm` 仅下午 | full |
| 单票上限 `max_single_position_pct` | (0,1]：买入后该代码市值 ÷ 组合总资产 ≤ 阈值，超出按剩余额度截断（不足 1 手跳过）。**NULL / 0 ＝ 不限制**（与接线前行为一致）；**只对实盘生效，回测不读** | 不限制 |
| 现金下限 `min_cash_reserve_pct` | (0,1]：买入后剩余现金 ÷ 组合总资产 ≥ 阈值，超出按剩余额度截断（不足 1 手跳过）。**NULL / 0 ＝ 不限制**；**只对实盘生效，回测不读** | 不限制 |
| 状态 | `active` 启用 / `archived` 归档 | active |

约束：`max_drawdown`、`daily_loss_limit` 必须在 `(0,1)`；被回测/实盘记录引用的组合、子策略不可删除（返回 409/400）。

### 子策略（Strategy）参数

> 子策略引用**一个已导入的公式**，买卖信号 = 该公式上配置的全部信号（signal_name + signal_type + trigger_value，见「五、公式管理」信号契约）。

| 字段 | 说明 | 默认 |
|---|---|---|
| 名称 | 子策略名称（非空） | — |
| 公式 | 必选；信号来自该公式 | — |
| 周期 period | `1m / 5m / 15m / 30m / 1h / 1d / 1w / 1mon`（注意**没有 60m**，两端不认） | — |
| 角色 role | `independent` 独立 / `master` 主 / `slave` 从 | — |
| 主策略 | 仅 `slave` 必填，指向**同组合**下 `master`（不可指向自身） | 无 |
| 从策略退出模式 | `independent` 自身信号/风控卖出 / `follow_master` 主策略卖出某股时从策略强制同步卖出该股（仅 slave 有效） | independent |
| 策略股票池 | 空 = 继承组合级；非空 = 本策略独立池。**slave 池必须 ⊆ 主策略池**，否则直接拒绝或该股永不成交 | 继承组合级 |
| 资金占比 | (0,1]：该策略占总资金上限（非预分，各策略之和可超 100%） | 60% |
| 持仓上限 | 该策略最大同时持仓数 | 5 |
| 单笔占用 | 单次开仓占总资金比例 | 10% |
| 止损 | 现价较**成本价**下跌 ≥ 该比例 → 清仓 | 5% |
| 止盈 | 现价较**成本价**上涨 ≥ 该比例 → 清仓 | 15% |
| 移动止损 | 现价较**持仓期最高价**回撤 ≥ 该比例 → 清仓（股价创新高后峰值自动上移） | 3% |
| 加仓阈值 | `-1`＝任何价格有 ADD 即加（含上涨/大涨）；`0`＝不涨即加（现价≥成本）；正常值＝现价较成本**下跌 ≥ 阈值**才加 | 5% |
| 加仓次数 | `[0,10]`，`0`＝禁加仓 | 2 |
| 加仓比例 | 每次加仓买入量占总资金比例 | 10% |
| 减仓比例 | 减仓（REDUCE）时卖出持仓比例 | 30% |

**信号执行优先级（总序）**：风控信号（止损 > 止盈 > 移动止损，触发任一即先出场）**高于**公式信号（OPEN 开仓 / ADD 加仓 / REDUCE 减仓 / CLOSE 清仓）。例：已涨到止盈点 → 先止盈清仓，同一 bar 不再执行 ADD。回测强制 **T+1**（当日买入次日才可卖）。

### 主从策略规则（易错）

- `slave` 只能买入 `master` **当前持有**的同一只股票（slave 池 ⊆ master 池，越界股永久无法成交）。
- `master` 清仓某股后：`slave` 不可再新开该股，但**存量可自行卖出**。
- `follow_master` 模式：`master` 卖出某股时，`slave` 若持有该股强制同步卖出。

### 配置校验速查（不满足直接 400）

- 角色/周期/交易时段/状态走白名单；`capital_ratio ∈ (0,1]`；加仓阈值须为 `-1` 或 `[0,1]`；加仓次数 `[0,10]`。
- `slave` 必须指定同组合下的 `master`（角色必须为 master，不能指向自己）。
- slave 池 ⊆ master 池（组合改股票池后会重校全部主从对）。

## 七、回测管理

### 7.0 启动回测前的准备（务必先满足，否则回测失败或零交易）

一条「今天可跑」的回测依赖下面全部成立：

1. **通达信** 已启动、可读历史数据（行情/日线/周线来源；`tdx_path` 指向其安装目录）。
2. **股票池**：组合绑定的股票池**已有成分股**（需先在通达信端存在，必要时先「同步」）。池空 → 无票可买，回测零交易。
3. **公式**：已导入通达信公式且**配置了信号**（trigger_value ∈ `{-2,-1,1,2}`），公式输出中确有与 `signal_name` 同名的输出线。
4. **组合策略**：组合非空、绑定股票池、含**至少一个子策略**；子策略 `period` 应与公式主图周期一致（"30 分钟公式挂到日线策略"是典型零信号坑）。
5. **区间**：`start_date < end_date`，且 `start_date` 不晚于今天。

平台提交回测时会做**信号预检**（非阻塞但务必看警告）：公式执行失败 / 信号输出线在公式中不存在 / 信号在区间内从未等于触发值 → 按警告修正后再跑，避免跑完才发现零交易。

### 7.1 发起回测

表单字段：

| 字段 | 说明 |
|---|---|
| 组合策略 | 选择一个组合策略（含其全部子策略与股票池） |
| 回测名称 | 记录名称 |
| 起止日期 | 开始 < 结束，且开始不晚于今天（TQ 拉不到未来数据） |
| 复权模式 | `front` 前复权（默认）／`back` 后复权／`dual` 前复权信号+后复权记账（**推荐**，模拟实盘口径） |

规则要点：
- 同一时刻最多 `max_concurrent_backtest`（默认 1）个回测运行，并发启动返回 HTTP 409；成功后前端轮询记录状态。
- 引擎：事件驱动（polars 核心），内嵌通达信 TQ 实时计算公式信号；**T+1 强约束**（当日买入次日才可卖）；成交按 `next_bar.open` 模拟并扣减组合费用参数（佣金/印花税/过户费/滑点）。
- **回测成本口径（2026-11-11 起含费）**：买入成本摊入佣金（含最低 5 元档）与过户费；卖出盈亏扣佣金、印花税、过户费；`strategy_cost` 归因成本同口径。此前的历史回测结果未计过户费，**需在新口径下重跑才严格可比**；若要复现旧数值，把该组合「过户费率」显式置 0 后重跑（`params_snapshot` 已冻结该字段）。
- **实盘成本不可与回测逐日对比**：实盘成本取柜台真实成交成本（含佣金/过户费，送转分红摊薄后可能为负或未知），回测成本是模型口径。
- 复权模式：长区间前复权有「加性压缩」导致历史价逼近 0/负的问题（假收益）；`dual`（前复权信号 + 后复权记账）规避假收益，**推荐**。
- 回测**仅支持单组合策略**（多组合联动只在实盘体现）。

### 7.2 回测记录列表

每条记录展示：ID、名称、组合策略、起止日期、状态（运行中/已完成）、操作（`查看` / `删除`，删除为级联删除，含详情/分析数据）。

### 7.3 回测详情分析（在线）

详情页是**多维分析 + 图表**，各区块：

- **关键指标摘要**：总收益/年化/最大回撤/夏普等。

- **净值曲线 / 回撤曲线**：与基准对比。
- **策略绩效评估**：组合整体 + 各子策略指标（收益、回撤、夏普、交易数等）。
- **收益分布**：月度收益热力图、年度日收益箱线图、年度月收益箱线图、各年年收益柱状图。
- **🔬 危机Alpha（折叠）**：十二模块完整防守评估 —— 核心结论 / 产品与基准走势 / 历届危机Alpha防守要点 / 极端下跌周 TOP / 全周期四象限分类 / 自然回撤事件清单 / 多宽基一致性 / 月度视角 / 动态相关性 / 代价检验（平均表现）/ 综合危机保护评分 / 全部下跌周明细。
- **市场状态（折叠）**：市场状态与超额收益 / 行业归因（结构对比） / 市场拥挤度（相对基准）/ 下跌周归因淋雨图 / 行业贡献分解 / 稳健性检验等。
- **🔬 稳健性检验（折叠）**：年度收益与最大回撤 / 三年滚动（CAGR + 最大回撤） / 累计交易实现 P&L 集中度 / 样本内·样本外对比（默认 75/25 自动切分）。提供 `重新计算` 按钮。
- **换池稳健性对比**：选择**其他股票池**（同参数仅换池）逐个重跑回测并对比（年化/最大回撤/夏普/胜率/盈亏比/交易数/仓位利用/基准/样本外 CAGR）。界面提供「推荐池」快捷选择（成长精选 / 红利精选 / 热点精选）。
- **风控与拦截统计**：按闸门聚合（触发次数/涉及股票数/时间范围），点某闸门可下钻逐条事件明细（时间/策略/代码/阈值/实际值/原因）。
- **交易明细**：全部成交记录（时间/策略/代码/买卖/价格/数量/金额/佣金/印花税）。
- **导出报告**：`导出 HTML 报告` —— 生成**单文件离线报告**（内联 ECharts 与全部图表/数据，无外链），双份内容可下载保存 / 打印 / 分享。

## 八、实盘交易

> 架构：Core（Python 3.13）按会话所选引擎下单/取数。可选 4 个引擎：`tdx`（同进程 TQ SDK）、`ths`（同花顺 UI 自动化）、`goldminer`（掘金终端内 HTTP 桥）、`iquant`（QMT 通道 HTTP 桥）。引擎未就绪（客户端未启动/未登录、依赖缺失、桥未运行、路径账号未配置）时启动直接返回 **503 + 中文提示**，不会静默换通道。

### 8.0 交易引擎与桥部署（换机必读）

| 引擎 | 实现 | 运行位置 / 端口 | 账户与限制 |
|---|---|---|---|
| `tdx` | 同进程 TQ SDK 直调 | 通达信客户端内 tqcenter | 用客户端当前登录账号；确认面板自动处置（`tq_trade.auto_confirm_dialog`），**无人值守首选** |
| `ths` | UI 自动化（键鼠） | 同花顺 `xiadan.exe` | `execute_mode=file_builtin`（默认，文件交接）/`direct`；撤单已自动化（F3 撤单页 OCR 定位委托行 → 双击 → 复读验证）；同通道仅 1 会话 |
| `goldminer` | HTTP 桥 `goldminer_bridge.py` | 掘金终端进程内，`127.0.0.1:7801` | 桥文件顶部 TOKEN/ACCOUNT/STRATEGY_ID |
| `iquant` | HTTP 桥 `iquant_bridge.py`（生产） | QMT 客户端内（Python 3.6.8），`127.0.0.1:8790` | **通道定位**：四条生产通道之一，与掘金/同花顺/通达信同级，平台正式接入并按生产标准维护。**账户资金属性**：410038214257（STOCK）是 QMT **仿真账户、账户内为仿真资金**，不是真实资金；`simulation`/`live` 两个模式位都指向它。`iquant_bridge_live.py`（8791 / CREDIT 410009993017）**非生产、未启用** |

- **桥只能由终端启动**：掘金桥/ QMT 桥都必须在对应终端里点「运行」（QMT 只启动 8790 生产桥这一个策略）。**禁止**用 `uv run` 或平台 venv 启动掘金桥（会把 gm SDK 装进平台环境，下次 `uv sync` 删掉后桥真断）；掘金终端关闭 = 桥停 = 报单按超时 expire 兜底。改桥文件后必须停止再启动策略才生效。
- **换机部署清单**：拷 `goldminer_bridge.py` 到掘金策略目录并把顶部 `TOKEN` / `ACCOUNT` / `STRATEGY_ID` 换成新终端分配值（仓库内 `STRATEGY_ID` 是占位符）；掘金部署文件用 UTF-8（无 BOM）+ CRLF 保存。QMT 只把 `iquant_bridge.py` 粘贴进客户端策略编辑器并运行（生产 8790 / STOCK）；`iquant_bridge_live.py`（8791 / CREDIT）非生产、未启用，换机不必部署，但两份文件须保持镜像（除 PORT / ACCOUNT / ACCOUNT_TYPE / TICK_TAG / `/ping` 的 service / 日志前缀 / strategyName 外逐字一致），改动需手动同步；**切真实资金须改桥文件顶部 `ACCOUNT` / `ACCOUNT_TYPE`（必要时 `TICK_TAG` / `DRY_RUN`）并重跑实盘验证，不能只改 `config.yaml`**；旧文件先备份（如 `*.bak.20261106-<HHMM>`）。
- **平台侧配置键**（根目录 `config.yaml`）：`iquant_bridge.simulation/live.base_url`、`goldminer.base_url`（及 `request_timeout_seconds=30` / `slow_response_seconds=15` / `slow_warn_interval_seconds=300`）、`tq_trade.*`、`ths_ui.work_dir/execute_mode/price_mode`。当前实际值以 `config.yaml` 为准（本机 simulation=8790、live=8790，两位都指向 QMT 仿真账户 410038214257，不使用 8791 信用腿）。
- **委托认领**：QMT/掘金桥把 `bridge_order_id` 写进柜台备注，按 remark 精确认领；通达信/同花顺不支持备注，走「代码+方向+数量+提交时间窗」模糊匹配（陌生遗留单会降级排除）。
- **撤单能力**：四个通道均由平台下发撤单——`tdx` / `ths` 走界面自动化；QMT / 掘金桥走桥端点 `POST /cancel`（按柜台委托号撤单，返回 `canceled` / `pending` / `not_found` / `rejected` / `failed`，`canceled` 按幂等成功处理，明确失败不误报成功）。老版本桥没有该端点（HTTP 404）时自动按「通道不支持撤单」跳过，退回超时 expire 兜底（柜台可能仍挂单，需人工撤）。撤单收敛为 `canceled` 后，开启 `requote_enabled` 的策略按 `requote_max_attempts` 追价重下剩余量（四个通道同一条提交链）。
- **启动前置**：实盘策略公式必须是通达信导入公式（`engine=tq`）；全自动仅支持 `signal_frequency == period`（跨周期信号请改用预警模式）；预警模式还会检查 TQ 预警可用性与公式输出线试算。
- **默认引擎**：`tq_trade.default_engine`（系统配置 → 通达信 TQ 通道，默认 `tdx`）。`live_sessions.engine` 为空的历史会话、已移除的旧 `qmt`（miniQMT）会话键都回退该默认；未配置/非法时回退 `ths_ui.enabled` 且依赖可用→`ths`，否则 `iquant`。
- **安全**：桥文件与 `config.yaml` 均含明文 TOKEN 与账户号，桥绑 `127.0.0.1` 无鉴权；分发/拷贝只在可信机器间进行，勿提交公开仓库或聊天群。

### 8.1 会话管理

- **新建会话**：会话名称 + 交易引擎（tdx / ths / goldminer / iquant）+ 组合策略（支持**多组合多选**，共享同一资金账户，各组合独立维护虚拟持仓与虚拟现金）。
- **模式**：`仿真 simulation` / `实盘 live` **只对 QMT 通道选桥**（simulation / live 两个位当前都指向 8790 的 QMT 仿真账户 410038214257，账户内为仿真资金，不是真实资金）；`iquant_bridge_live.py`（8791 / 信用账户 CREDIT）非生产、未启用。其它引擎的账户由通道自身决定，模式不改变下单账户。
- **实盘资金基准 `live_capital`**：填账户**总资产**（可用资金 + 持仓市值），留空则用组合 `initial_capital`；启动后继承的存量持仓市值会从起账现金中扣除，避免与基准重复计入（只填可用资金会低估总资产）。
- **启动 / 停止**：启动后进入轮询（行情/订单/账户），实时事件经 **SSE**（`/api/live/sessions/{id}/stream`）推送前端，非轮询。
- **删除**：删除会话记录。
- **多会话并行**：跨引擎可并行（不同账户）；**同一引擎同时仅一个会话**；同一组合挂多个会话做复制交易时必须选不同引擎，各账户独立记账。
- **外部信号文件路径 `signal_file_path`**（可选，会话级）：留空 = 走 TQ 公式计算信号；填写 = 读取通达信「条件预警」动态输出文件（GBK 追加写入）的新增信号行，绕过 TQ 公式的周期限制。**填写即替换信号来源**，该会话不再跑 TQ 公式（两条路径互斥，不双触发）；风控/仓位/资金等限制仍沿用回测口径。四个引擎通用，仅自动模式生效（预警模式不读取该文件）。
  - **买卖方向**：信号动作分买入类（OPEN / ADD）与卖出类（REDUCE / CLOSE），方向由该策略公式信号配置的 `signal_type` 决定（预警文件本身不含方向列）。
  - **买入类**：沿用原有开仓闸门（资金占比 / `max_positions` / 单仓金额 / 敞口上限 / 可用现金），满槽或已持仓跳过。槽位上限取**该组合自己的 `strategies.max_positions`**（各组合可不同）；组合缺失该值时**跳过槽位闸并告警**，不写死 5。
  - **卖出类**：不做仓位与资金检查，但受两条硬约束——**无持仓不卖**（不得卖空）、**T+1 实际可用为 0 时拒绝**（沿用实盘 T+1 可用股数校验，不绕过）。
  - **减仓比例**：预警文件 8 列没有数量/比例列，**REDUCE 未给出比例时按清仓执行**（日志与风控事件明确标注「未给出比例，按清仓执行」，不静默猜测百分比）；CLOSE 恒清仓。
  - **去重**：同代码 + 同日 + 同方向各认第一条（买卖各自独立、互不吞并；同方向重复推送不重复下单）。未知/不可解析的动作一律忽略并节流告警（每 50 条一次），绝不猜测方向或默认成买入。
  - **与 14:52 提前收盘价轮次**：卖出信号在 14:52 那轮照常生效（该轮本就补跑风控 + 消费文件信号）。
- **日线级别默认口径（1d / 1w / 1mon）**：都等**周期收盘价落定之后**在 15:05 轮次用**完整 bar** 算信号，**次一交易日开盘执行**；14:30 只做日终估值 / 日亏 / 熔断恢复，**不再驱动日线级信号**。1w 只在每周最后一个交易日、1mon 只在每月最后一个交易日的 15:05 轮次计算（周五 / 月末休市自动前移到前一交易日），其余日子跳过。15:05 轮次算出的单**强制次日执行**（`risk_timing=immediate` 也一样——收盘后报单报不进交易所）。
- **14:50 提前收盘价 `advance_close_enabled` / `advance_close_time`**（会话级，B 可选增强，默认关 / `14:51`）：**开启后仅日线 1d 提前**——14:50 用快照合成 1m bar 的收盘价定信号，**委托价取 14:52 起始 1m bar 的开盘价**（考虑 14:51 报单的报价时延；取不到则回退 14:51 起始 bar 的开盘价并推送 `advance_close_exec_price_fallback` 风控事件；两者都取不到则该股本日不下单并推送 `advance_close_exec_price_missing`，**不伪造价格、不退化成市价**）。该轮 1d 信号**当日尾盘提交成交**（不受 `risk_timing=next_day` 的次日顺延）。**周线/月线不受影响**（仍走 15:05 收盘落定 + 次日执行）。数量/资金/仓位仍按 14:50 收盘价计算，**持仓成本以柜台成交回填 / 券商快照为准**。四引擎通用（tdx/ths/预警/goldminer 用快照合成，iquant 用桥 1m 行情）；仅自动模式、仅实盘生效（回测忽略）；同一交易日只执行一次（跨重启幂等，DB `advance_close_done_date`）；会话须在 14:50 前启动。`advance_close_time` 限定 14:51–14:59，实际轮次不早于 14:52（委托价需要 14:52 起始 1m bar）。
- **与「风控执行时点 `risk_timing`」的区别**：`advance_close_*` 是会话级，决定**日线信号/风控用哪根 bar 的价格、在哪个时点算**；子策略的 `risk_timing`（`next_day` 默认 / `immediate`）是策略级，决定**算出来的单什么时候提交**。**提前收盘价轮次的 1d 信号固定当日提交（等价于该轮强制 immediate）**，不受 `risk_timing` 影响；15:05 收盘落定轮次则无条件次日执行；其余盘中轮次 `next_day` = 次日执行（**盘前集合竞价开启时优先在 09:15–09:20 报出，未报成才回落首根分钟 bar 约 09:31**）、`immediate` = 当日提交。
- 会话列表展示：ID、名称、引擎、模式、关联组合（`active` / `circuit_broken` 状态徽章）、操作。

### 8.2 实时事件日志（SSE）

顶部事件面板实时流转以下事件类型（带颜色标识）：

`signal 信号` / `order 委托` / `trade 成交` / `position 持仓` / `risk 风控` / `decision 决策拦截`（心跳 `ping` 不进日志）。日志上限 200 条滚动。`order/submitted` 不再重复推送两条；受理未认领时只补一条 `order_unconfirmed` 决策事件说明状态。

### 8.3 工作台（按会话）

- **持仓**：实时持仓（虚拟持仓，多组合独立）。
- **委托**：委托状态 `已提交/全部成交/部分成交/已拒绝/已撤单`。
- **成交**：成交明细（含 T+1 可用股数实时校验）。
- **决策/拦截**：逐条决策事件 + 聚合统计（按闸门：止损/止盈/移动止损/公式信号/熔断……）；拦截数量显示「请求 → 实际（全拦→0/缩减→N）」。实盘另有：`sell_scope`（`platform_only` 下纯外部仓不代卖，记 `skip`）、`inflight_sell`（同（策略, 代码）在途卖单去重：目标量减在途 ≤0 整单跳过、>0 按差额收窄）、`out_of_pool_position`（池外外部仓每日一条汇总 `notice`，不进风控/不占槽位/不代卖）。

### 8.4 熔断恢复

组合触发 `max_drawdown`（累计 3 次）或 `daily_loss_limit` 熔断后状态为 `circuit_broken`，该组合暂停开仓（不清仓）。可点击 **恢复** 手动清零熔断计数并恢复开仓（会弹确认框）。

> 实盘收入规则：信号优先级 = 风控 > 公式；多周期可同时触发（一个 5m bar 同时命中多个周期）；T+1 实时查询可用股。

### 8.5 次日盘前（集合竞价）执行日线信号单（默认开启）

系统配置 → 左侧导航 **「盘前集合竞价」** 分组（标题写明「全引擎生效」，**不是**通达信专属参数）里的 **启用盘前集合竞价** 开关，**默认开启**（`tq_trade.pre_open_auction_enabled`；`config.yaml` 未写时取代码默认 true）。该开关对通达信 TQ / 同花顺 / 掘金 / QMT 四条交易通道均生效，与各通道自身参数相互独立。

| 模式 | 行为 |
|---|---|
| 开启（默认） | 交易日 **09:15 至「盘前执行结束时间」（默认 09:20，左闭右开）** 把「当日 due」的 deferred 单直接报进集合竞价；不依赖 1 分钟 bar。**`1d`/`1w`/`1mon` 同口径生效**（due 判定 = `signal_bar_date` 的下一交易日），分钟信号与未到 due 的顺延单不走盘前 |
| 关闭 | 旧行为：信号在前一交易日收盘后落为 `deferred`，**次日首根完成的 1 分钟 bar（约 09:31）** 放行 |

- **委托价**：信号价（信号 bar 收盘）× (1 ± 让价幅度，默认 2%)，并夹进当日涨跌停（买 `涨停价−1 跳`、卖 `跌停价+1 跳`；通道取不到涨跌停时只按让价）。集合竞价按统一开盘价成交，限价只作上限；刻意不推到涨跌停板，避免未成交余量全天挂板追价。
- **09:31 兜底改为限价**：未在盘前报出的单由当日首根 1m bar 放行，**限价 = 该 bar 的开盘价**（取不到时退回实时 close 并记 `deferred_release / action=fallback` 风险事件），夹涨跌停后 quantize 到分；`tq_trade.deferred_release_ensure_fill`（默认 **false**）开启后才改用对手价「保证成交」。
- **不会重复下单**：每单每日只尝试一次；盘前已报出（含受理未确认）的单 09:31 不再重报；被闸门拦截/异常/通道明确拒单的单保持 `deferred`，由 09:31 首根 bar 路径兜底重试——最坏是「盘前没报成、09:31 报一次」。
- **开盘后撤单校验**：若开盘价已越过盘前限价（买限价 < 开盘价、卖限价 > 开盘价），判定必然未成交 → **主动撤单**并记 `pre_open_auction / action=cancel`（`rule=open_crossed_limit`）。**注意 09:20–09:25 为交易所不可撤窗口**，该时段内不发撤单请求，顺延到 09:30 之后由超时路径处理。
- **可观测**：工作台「决策/拦截」可见 `pre_open_auction` 闸门的 `release`（放行，含委托价）/`block`（跳过原因）/`cancel`（开盘越价撤单）；日志以 `[pre-open]` 前缀与首根 bar 路径区分。
- **价型**：盘前单**按单**下发 `price_type=limit`，**不再要求**会话级或 `config.yaml` 配 `price_type: limit`；HTTP 桥通道的闸门判据为桥 `/ping` 自述支持 `limit` 或提供 `/price_limit`（通达信/同花顺按各自通道能力），并保留「本会话盘前单 `/order` 回显非 `limit` 就拦」的兜底。

### 8.6 引擎/账户独占、资金基准重置与参数绑定（2026-11-16）

**启动闸（按 C1 → C2 → C3 顺序，全部返回结构化 409）**

| 闸 | 判据 | `data.rule` | 说明 |
|---|---|---|---|
| 引擎独占 | 同一 `engine` 全平台只允许一个 running/stopping 会话 | `engine_exclusive` | 每个引擎背后只有一个本地入口（通达信客户端 / xiadan.exe / 8790 QMT / 7801 掘金），同引擎双会话会双份记账、互相吃单 |
| 账户独占 | 同一 `account_key` 跨引擎只允许一个 running/stopping 会话 | `account_exclusive` | 取键顺序：桥 `/ping` 的 account → `config` 的 `account_id`（tdx/ths 为各自 `account`）→ 降级 `engine:<key>`；落库在 `live_sessions.account_key` / `account_key_source` |
| 键鼠互斥 | `tdx` 与 `ths` 同时运行 | `keyboard_exclusive` | 默认软拦：未带 `ack_keyboard_risk=true` 返回 409 要求确认；带 ack 放行并留 WARNING + 决策事件；`tq_trade.keyboard_conflict_hard_block=true` 升级为无条件 409 |
| 会话总量 | 同时运行（running/stopping）> **4** 个 | `session_limit` | 显式上限 `MAX_ACTIVE_LIVE_SESSIONS=4`；停止一个即可再启 |

- 409 的 `data.occupied_by` 为占用方摘要：`{session_id, name, engine, account_key, account_key_source, status, since}`。
- `status=stopping` **仍算占用**（防「刚停就启另一个」双开）；引擎停止收敛后置 `stopped` 才释放；stopping 超过 120s 未收敛且注册表无引擎 → 视为僵尸自动释放并记 WARNING。
- 新建会话时若目标引擎已被占用，响应带 `warnings`（不阻断），提示「启动前需先停止该会话」。

**资金基准与重置**

- 会话字段：`baseline_mode`（`total_asset`＝按真实总资产 / `manual`＝手工填写）、`baseline_value`（元）、`baseline_version`（每次重置 +1，顺延单据此打版本）、`live_capital`（兼容列，语义同基准）。
- 接口：`POST /api/live/sessions/{session_id}/portfolios/{portfolio_id}/reset-baseline`（界面入口：实盘会话 →「重置资金基准」）。
- 规则：**只缩不放**——填写值 > 真实总资产直接 400；不填则取当日真实总资产。**非交易日 403「今天不是交易日」**；交易日 09:15–11:30 / 13:00–15:00 盘中 403，收盘后/盘前允许。
- 重置会成套重锚 `peak_value` / `prev_close_value` / `last_bar_total_value` / `last_bar_date`（DB 与运行中内存同时更新），删除旧增量回测 checkpoint 并重设接缝；**不清零** `circuit_breaker_count`、不解锁手动恢复、不改暂停/熔断标志，也不写 `live_cash_flows`（不动外部净流入与风控净值口径）。
- 账户预览：`GET /api/live/account-preview?engine=&mode=`（`mode` 缺省取该引擎最近会话的实际 mode，避免 live/simulation 指向不同桥地址时预览到错账户）。

**H2 参数绑定（`live_sessions.backtest_record_id`）**

- 新建会话可绑定一条回测记录（`POST /api/live/sessions` 的 `backtest_record_id`；软引用不设 FK）。本期**后端字段与接口已就位，前端表单入口待后续**。
- 启动时把 `backtest_records.params_snapshot` 与当前组合参数比对：只比快照中存在的组合级字段、数值归一后比较；回测 run 级覆盖字段（费用预留/债券 T+0/成交量上限/权益上限/复权口径等）不参与比对，避免假漂移。
- 默认**只告警**：WARNING + 决策事件 `gate=params_drift`（列出差异字段），**绝不阻断启动**；`tq_trade.params_drift_block=true` 才升级为 409 `rule=params_drift`。
- 查询接口：`GET /api/live/sessions/{session_id}/params-drift`（未绑定返回 `checked=false`）；会话详情 `GET /api/live/sessions/{session_id}` 也返回 `backtest_record_id` 与 `params_drift`。

### 8.7 外部现金流台账（出入金 / 分红，2026-11-16）

账户有外部资金进出时**必须登记台账**，否则虚拟净值、收益率、回撤与日亏会被外部资金扭曲（入金像盈利、出金像回撤，可能误触熔断）。

- 接口：`GET /api/live/sessions/{session_id}/cash-flows?portfolio_id=&limit=200`（列表 + 各组合累计净流入）；`POST /api/live/sessions/{session_id}/cash-flows`（登记一笔）。
- 请求体：`portfolio_id`（必填）、`flow_type` ∈ `deposit`（入金）/ `withdraw`（出金）/ `dividend`（分红）/ `other`、`amount`、`flow_date`（可选 `YYYY-MM-DD`，默认今天）、`note`（可选）。
- 金额符号：`deposit` / `dividend` / `withdraw` **一律传正数**（方向由类型决定：入金、分红为流入，出金为流出）；`other` 按符号判方向（正=流入、负=流出）。落库为有符号金额。
- 记账口径：虚拟现金随台账即时加减（运行中会话立即生效；停止后下次启动从台账重放）；**净值 / 收益率 / 回撤 / 日亏按「总市值 − 累计净流入」计算**，与回测（无外部现金流）口径一致。
- 柜台现金与虚拟现金不一致只记 `cash_diff` 告警（10 分钟节流），**绝不改账**；改账只能走台账或成交回填。资金基准重置（8.6）也不会写台账。
- 界面入口：本期仅后端接口（工作台事件流会展示 `cash_flow` 台账事件），前端登记表单待补。

### 8.8 本轮新增/落库的工作台决策事件（2026-11-16）

以下事件现在**同落 `live_decision_events`**（layer=risk/execution），刷新页面后仍可在工作台「决策/拦截」中查到（此前只推 SSE，刷新即消失）：

| 事件（`gate` / `action`） | 触发场景 | 说明 |
|---|---|---|
| `split_children_lost` / `drop` | 停止会话时拆单队列里还有未提交子单 | 记剩余笔数与股数随队列丢弃。**平台不自动补单**，需人工确认是否补报；在途子单由停止撤单/超时 expire 兜底 |
| `split_children_lost` / `notice` | 重启恢复时按 bar 委托标记（`seq>0`）+ 在途子单反查 | 只告警「可能丢失的剩余量」，不自动补单、不落库重放 |
| `deferred_release` / `drop` | 09:31 放行后未真正提交（资金/仓位/时段/去重/T+1 可用不足等闸门拦截） | 取消原 deferred 单（宁可漏一次，不冒重复成交风险），防重启后重复恢复 |
| `deferred_release` / `fallback` | 取不到当日首根 1m 开盘价 | 退回实时收盘价放行，标注 `price_source` |
| `deferred_dropped_stale` | 重启恢复时顺延单已过期 | 作废并留痕 |
| `daily_bar_freshness` | 日线轮次因「取数为空 / 最新日线非当日」跳过 | 每交易日一条，提示「今天日线策略没跑」 |
| `valuation_missing_price` | 持仓三级估值价全缺（最后已知价/成本/前收） | 市值按 0 计，净值与回撤可能偏低；每组合每代码每日一次 |
| `cash_diff` | 柜台现金 ≠ 虚拟现金（扣在途冻结后） | 10 分钟节流，只告警不改账 |
| `equity_deviation` | 真实总资产 vs 虚拟净值偏差 > 20% | 每会话一次，不改账 |

> 日线轮次的完成标记只在**整轮驱动成功后**写：某个组合因桥离线跳过时，本轮不标完成，60 秒主循环会自动重试（已成功的组合/周期不重复驱动），不会整天丢信号。

## 十、关键业务规则一页纸

- **股票代码**：统一带后缀（`000001.SZ` 等，通达信规范）。
- **信号优先级**：风控（止损/止盈/移动止损）> 公式信号（OPEN/ADD/REDUCE/CLOSE）。
- **加仓阈值特殊值**：`-1` = 跳过回撤检查只要有 ADD 即加（含上涨/大涨）；`0` = 不涨即加；正常 1%~20% 逢跌加仓。`max_add_count` 次数上限仍生效，风控优先级仍高于 ADD（到止盈点先止盈不加）。
- **资金模型**：策略资金占比是持仓上限（非预分），多策略之和可超 100%。
- **T+1 约束**：回测强制 T+1；实盘实时查可用股数。
- **熔断**：`max_drawdown` → 次日恢复（累计 3 次后转手动恢复）；`daily_loss_limit` → 当日暂停，次日恢复。熔断仅暂停新开仓，不清仓。
- **主从策略**：从策略只能买主策略当前持有的同一只股票；主策略清仓后从策略不可新开仓但存量可自行卖出。
- **多周期同时触发**：一个 5m bar 可能同时触发多周期公式（5m+30m+60m）。
- **多组合实盘**：一个会话可含多组合，共享同一资金账户下单，各自独立虚拟持仓/现金；Core 重启时从成交记录聚合重算虚拟持仓与现金。
- **实盘资金基准**：`live_capital` 按账户**总资产**（可用资金 + 持仓市值）填写；留空回落到组合 `initial_capital`；继承的存量持仓市值从起账现金中扣除。
- **原有持仓**：账户存量持仓中属于本会话股票池的部分导入虚拟账本，按真实成本纳入止损/止盈/移动止损风控；非策略买入的部分在工作台以灰色「原有持仓」标注。**池外外部仓不再兜底归属**：只进持仓展示与对账，不进风控、不占槽位、不代卖，每会话每日一条 `out_of_pool_position/notice` 汇总事件。
- **成本未知**：柜台成本 ≤ 0（送转分红后为负，或柜台返回 0）视为成本未知，不参与止损/止盈/移动止损，展示「成本未知」（不再回退市值÷数量）。
- **实盘卖出范围**：`live_sell_scope=full` 卖整仓（默认）；`platform_only` 只卖平台自建仓，纯外部仓不代卖（`gate=sell_scope/skip`）。
- **实盘槽位上限**：取**各组合自己的 `strategies.max_positions`**（各组合可不同）；组合缺失该值时**跳过槽位闸并告警**，不写死 5。
- **卖出在途去重**：同（策略, 代码）已有未结卖单时，目标量先减在途未成交量——≤0 整单跳过、>0 按差额收窄（`gate=inflight_sell`）。
- **回测仅单组合**：多组合行为只在实盘体现。
- **交易日历**：优先取数据源/掘金桥 `/calendar`，不可用回退内置官方休市表（目前只覆盖到 2026 年）；覆盖范围外的未来日期按工作日 fail-open，并在启动时打 WARNING，需在交易所发布后补表。
- **错周期风控**：默认只在策略**自身周期**的边界 bar 上评估止损/止盈/移动止损（1m/5m 等错周期 bar 只更新价格快照；周线/月线同样只在自身边界评估——对齐回测）。会话级三态 `intraday_mismatched_risk_enabled` 可覆盖：NULL 跟随全局（默认 false）、1 强制开启（旧行为：任意 bar 都跑风控）、0 强制关闭。风控口径**只用 close**（不用 high/low/均价）。
- **回测成本含费**：买入成本摊入佣金（含最低 5 元）与过户费；卖出盈亏扣佣金、印花税、过户费；`strategy_cost` 归因同口径。**实盘成本取柜台真实成本（含费、含送转摊薄），不可与回测逐日对比**；2026-11-11 前的历史回测需在新过户费口径下重跑才严格可比（复现旧值：组合过户费率显式置 0 后重跑）。
- **盘前集合竞价**：默认开启，`1d`/`1w`/`1mon` deferred 单均在 09:15–09:20 报入；未报出的由 09:31 首根 1m bar 以「开盘价限价」兜底（`deferred_release_ensure_fill` 开启才用对手价）；开盘价越过限价即主动撤单（09:20–09:25 不可撤窗口除外）。
- **基准口径**：绩效对比基准 = 组合绑定的基准指数，按同期行情归一。
- **资金基准重置**：`POST /api/live/sessions/{id}/portfolios/{pid}/reset-baseline`，只缩不放（填写值 > 真实总资产 400）；非交易日与盘中（09:15–11:30 / 13:00–15:00）403；成套重锚四个锚点、`baseline_version+1`，不清熔断计数/不解锁手动恢复，详见 8.6。

## 十一、数据与备份

- 全部数据在 `data/dev.db`（SQLite 单文件），含：股票池、公式、组合策略、回测记录、回测快照、评估指标、危机Alpha/市场状态/稳健性分析、决策事件、实盘会话/委托/成交/持仓。
- **备份**：直接复制 `data/dev.db` 即可（建议在程序停止时复制）。
- **数据库迁移**：表结构变更走 Alembic，首次启动自动执行（禁止手动改表）。
- **安装器首次启动**：安装完成后「立即启动」以**原用户身份**（`runasoriginaluser`，非提权管理员）运行，避免把 `data/`、`config.yaml` 写成管理员独占的文件；后续普通用户即可正常读写。
- **构建档案**：安装目录 `build-info.json` 记录 `app_version` / `build_mode` / `build_time` / `git_commit` / `git_dirty` / `frontend_dist_mtime`。前端补丁包（`--web-only`）**不改写 `app_version` 与构建时间**，只追加 `frontend_patch_time`，因此档案始终反映 exe 的真实版本；出包前会强校验版本一致且工作区干净（详见 `packaging/README.md`）。
- **风险文档**：风控文档/草稿类规划放在 `docs/risk/`、`docs/draft/`，不进包。

## 十二、常见问题

**Q0：能否把打包目录拷到别的电脑直接运行（无 Python 环境）？**
可以。安装包为 Nuitka 独立打包，解释器 + 全部依赖均随包，目标机无需安装 Python。要求：
1. **Windows x64** 电脑，且已安装**通达信 TQ 客户端**（行情/历史数据来源）。
2. 用安装包装机（不要只拷 exe，依赖在 `_internal\` 等子目录）；安装时保持勾选
   「登录后自动启动并保持运行」，安装器会注册计划任务 `TQ-IQuant-Supervisor`
   （登录时运行 `tq-iquant.exe --supervise`）。
3. **修改通达信路径**：安装目录 `config.yaml` 的 `tdx_path` 默认是构建机路径（如 `D:\zd_zyb`），需改成目标机通达信安装目录——可启动前直接编辑该文件，或启动后在「系统配置 → 通达信目录」设置并保存（配置随 exe 同级目录读写，可移植）。
4. 首次启动自动创建 SQLite 数据库并执行全部 Alembic 迁移，无需手动建库。
5. 仅实盘需要额外准备交易客户端：通达信 TQ（同一客户端）、同花顺 `xiadan.exe`、掘金终端、QMT 通道客户端，并运行对应桥策略；纯回测不需要。
6. 若杀毒软件拦截 exe，添加信任后再启动。

**Q1：双击 tq-iquant.exe 后界面 30 秒仍未就绪**
1. 先看 `<安装目录>\logs\supervisor.log` 与 `logs\core.log`（自愈模式）或 `logs\core.log`
   （单进程模式）的报错；子进程启动崩溃原因在 `logs\supervisor-child.log`。
2. 端口是动态的（8888~8898），实际端口见 `data\runtime\server.json`；用
   `netstat -ano | findstr <端口>` 查占用，关闭占用程序（或删掉 server.json 后重试）。
3. 杀毒/安全软件是否拦截 exe，添加信任。
4. 保持整个目录完整，不要单独移动 exe（依赖 `_internal/`）。

**Q2：回测发起失败"/ 复权模式仅支持 front/back"**
说明运行的是旧版后端。封装版请重新打包或确认使用最新 exe；源码版请重启 uvicorn（旧进程不会热加载已提交代码）。

**Q3：离线报告导出 500**
确认包装含 `echarts.min.js`（`main/dist/tq-iquant/echarts.min.js`，1.1MB）。源码版需 `web/node_modules/echarts/dist/echarts.min.js` 存在。

**Q4：实盘看不到行情/无法下单**
1. 确认所选引擎的前置条件：`tdx` 需通达信客户端已登录且 tqcenter 可用；`ths` 需 xiadan.exe 已登录；`goldminer` 需掘金终端内 `goldminer_bridge.py` 在运行（7801）；`iquant` 需 QMT 客户端内 `iquant_bridge.py` 在运行（8790 生产桥）。
2. 启动会先探活，未就绪直接返回 503 + 中文提示，不会静默换通道；逐条按提示处理。
3. QMT 的 simulation / live 两个模式位都指向 8790 同一个生产桥；桥地址以 `config.yaml` 为准（页面不提供该项）。

**Q5：如何让封装版使用最新数据**
封装包自带独立 `data/`（构造时保留旧包数据）。如需同步源码版数据库，停止 exe 后将源码 `main/data/dev.db` 覆盖到 `main/dist/tq-iquant/data/dev.db`（并删除残留的 `dev.db-wal`/`dev.db-shm`）后重启。

**Q6：开发模式改了后端不生效**
uvicorn 若未带 `--reload` 或 reload 失效，重启 `uv run uvicorn core.main:app --reload` 后再试。
