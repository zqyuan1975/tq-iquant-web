# 投资看板（Investment Board）实施方案

- 日期：2026-11-21
- 性质：实施设计（阶段 1 交付物）。阶段 2/3 按本方案落地，代码尚未改动。
- 口径基准：`docs/plans/2026-11-21-行业评级系统与门控公式比对.md` §12（公式真值）、§13（超买超卖重定义）。

## 0. 目标与硬约束

**目标**：新增「投资看板」栏目，① 整体承接备选股池页的「市场多空状态」卡（原位置移除，不留双入口）；② 把 `D:\行业评级系统` 的产品能力（128 个 881 二级行业相对大盘的多头先后、行业成分股相对行业的领先、日线/30m 双视图、强度分级与榜单）迁入本项目。

**硬约束**：

1. **只读看板**：不接下单、不进 `market_gate`、不改策略/风控行为；不写任何实盘或回测业务表。
2. **公式唯一实现来源 = 本项目 `main/core/engine/market_gate.py` 内核**，不移植行业评级系统的 Python 版本；后者只作页面形态与交互蓝本。
3. **方向统一 ENH**：`states` 取 `m_enh`（原文 `多头强度:IF(UP_ENH,…)` 口径），不再存在 M/ENH 双口径。按 §12：基准 000001.SH 在 940 天中有 11 天「只有 M 判空」，统一后不再拦。
4. **补 `偏离分_空`**：`IF(偏差率<-3,10,IF(偏差率<-1,5+(-1-偏差率)*2.5,0))`，空头强度六项齐备。
5. **超买超卖用 §13 方案 A**：`z=(BIAS−mean₂₅₀(BIAS))/sd₂₅₀(BIAS)`（参数**不含当日**），`z≥+2.5` 超买、`z≤−2.5` 超跌，多空对称；`JD` 与 `CH/CL` 轨道降级为**二级过滤展示**，不作必要条件。不再使用 `ABS(BIAS_AO)>5 AND EXT_JD_DN AND C<CL`。
6. **名单严格 128**：来自 `TQData.get_industry_list()`，落库快照并校验（`881999` 之类一律剔除）。
7. **最小根数**：`<300` 根不输出方向（§12 M3），页面标 `数据不足`。
8. **30m 只用已闭合 bar**，并记录 `effective_from = 下一根 bar`（闭合后下一根生效）。
9. 数据自建：行情走本项目 TQ 通道 + 本地通达信；不读行业评级系统的 parquet / `min30_timeline`。
10. 不启停实盘会话；不改 `capital_enforce_enabled` / `cash_outlet_mode` / `sell_scope`；不动 `live.native_minute`；保留未跟踪产物与他人改动。

## 1. 页面信息结构（阶段 3）

路由：`/investment-board`，`name: investment-board`，懒加载 `views/InvestmentBoard.vue`；侧边栏「研究」组首位（在「备选股池」之上），图标沿用 `pools`/新增 `board`。

```
投资看板
├─ A 口径条（顶部）
│   公式版本 tqgate_py_v2 ｜ 方向口径 ENH ｜ 超买超卖 z(250,k=2.5) ｜ 数据时间 ｜ [刷新]
├─ B 大盘多空状态卡（自备选股池整体迁移）
│   方向 / 强度 / 起始日 / 持续交易日 / 最近 5 次转折 / 陈旧提示
├─ C 行业榜单（Tab：日线 | 30分钟）
│   三张分类卡：持续领先(按 bull_dur↓) ｜ 由空转多(bull_dur=1, 按强度↓) ｜ 超额领先(bull_dur>基准, 按领先天数↓)
│   表格列：行业 / 方向 / 强度 / 等级 / 持续 / 偏离z / 超买超卖 / 相对基准领先 / 数据时间
│   交互：点击行 → 右侧抽屉（D）
├─ D 行业详情抽屉
│   行业头部：方向、强度、等级、bull_dur、bias/bias_z、JD 过滤、轨道过滤
│   成分股领先榜：个股 / 方向 / 强度 / bull_dur / 领先行业天数 / 超买超卖
├─ E 口径说明（折叠）
│   本项目 ENH 口径 vs 行业评级原实现的三处差异（WO ROUND / 3.1416 / 偏离分_空）、
│   超买超卖重定义理由、128 名单与最小根数规则
└─ F 统一市场状态面板（自备选股池迁移，E5 只读说明，避免双入口）
```

字段语义：`direction∈{-1,0,1,2}`；`strength 0–100`；`level∈{strong_bull,medium_bull,weak_bull,strong_bear,medium_bear,weak_bear,none}`（修正行业评级把空头强档映射为 `weak` 的缺陷）；`bull_dur/bear_dur` 为连续 bar 数；`lead_days = 行业 bull_dur − 基准 bull_dur`。空值一律显示 `—`，不显示 0。

**备选股池页改动**：删除 `StockPools.vue` 中市场多空状态卡（L21-60 状态、L71-131 加载、L139-220 UI）与 E5 面板及其 API import；其余股票池功能零改动。

## 2. 后端数据层与接口

### 2.1 计算内核（唯一实现来源）

新增 `main/core/engine/rating_core.py`，把 `compute_gate_states`（`market_gate.py:401-518`）的指标段抽成：

```python
def compute_rating_frame(ohlcv) -> pd.DataFrame
# 列：date, ao/ah/al/bo/zo/co/ch/cl, jd, bias, jj,
#     m, m_enh, up_enh, down_enh,
#     up_str, dn_str, cur_str, level,
#     bias_z, overbought, oversold, jd_filter, channel_filter,
#     bull_dur, bear_dur, bars
```

- 复用 `market_gate` 现有私有 helper（`_ma/_round2/_round_half_away/_ma/_ref/_if/_gt/_lt/_count/_sum`），不复制公式。
- 相对 `market_gate` 的**口径变更**（同步回写至门控，版本号 → `tqgate_py_v2`）：
  1. 方向取 `m_enh`（原 `m`）；
  2. 空头强度补 `偏离分_空`；
  3. `<300` 根直接返回空 frame（不输出方向）。
- 超买超卖：`bias_z` 用 `bias.rolling(250, min_periods=250).mean().shift(1)` 与 `.std().shift(1)`；`overbought = bias_z>=2.5`，`oversold = bias_z<=-2.5`；`jd_filter = jd>25 / jd<-25`、`channel_filter = C>CH / C<CL` 仅参与展示。
- `bull_dur/bear_dur`：按 ENH 方向做连续计数（等价 `BARSLAST(UP_ENH=0)`）。

`compute_gate_states` 改为调用 `compute_rating_frame`，返回 `({date: m_enh}, {date: round(cur_str)})`，行为影响即 §12 的 11/940 天。

### 2.2 行情与计算服务

新增 `main/core/services/board_service.py`：

- `refresh_universe(db)`：`TQData().get_industry_list()` → 严格过滤 `^881\d{3}$`、去重、断言 128；写 `board_industries`（新增/失效标记）。
- `compute_industries(db, period, as_of=None)`：对每只行业取 `bar_count = 320`（日线）/ `320`（30m）根，`build_gate_ohlcv(code, start, end, period)`（TQ 通道，`dividend_type="front"`），`compute_rating_frame` 后 upsert 当日快照。
- `compute_stocks(db, period, industry_codes)`：成分股来自 `TQData().get_stock_list_in_sector(industry)`；日线全量、30m 仅「日线 `bull_dur==1` 的行业」（上限 20 个行业），控制成本。
- `run_snapshot(db, period, scope, trigger)`：写 `board_runs`（running→ok/partial/failed），逐标的 try/except 记 `skipped`，不因单只失败中断。

### 2.3 接口（`main/core/api/investment_board.py`，prefix `/api/investment-board`）

| 方法 | 路径 | 说明 | 缓存 |
|---|---|---|---|
| GET | `/summary?period=1d` | 大盘卡（复用 `fetch_gate_status`）+ 等级计数 + 最新 run + 参数口径 | 60s |
| GET | `/industries?period=1d&date=&sort=&order=&level=&limit=` | 行业榜（默认按 `bull_dur` 降序） | 60s |
| GET | `/industries/{code}?period=1d&date=` | 行业详情 | 60s |
| GET | `/industries/{code}/stocks?period=1d&date=&sort=lead_days&limit=50` | 成分股领先榜 | 60s |
| GET | `/leaders?period=1d&type=sustained|reversal|excess` | 三个分类卡 | 60s |
| GET | `/runs/{id}` | 刷新任务状态 | 无 |
| POST | `/refresh` `{period, scope}` | 触发后台刷新，返回 `run_id` | 无 |
| GET | `/meta` | 公式版本、z 参数、128 名单校验结果、数据时点 | 300s |

响应统一 `ok(...)`（`core/api/response.py`），错误走 `err(...)`；只读，无写业务表。

缓存：进程内 TTL（参照 `market_gate_service._cache`）；快照表是唯一数据源，缓存只挡高频轮询。刷新粒度：手动刷新只重算当日快照，不重算历史。

## 3. 日线 / 30m 计算时点

| 周期 | 触发 | bar 可用性 | 落库语义 |
|---|---|---|---|
| 日线 | 每个交易日 **15:10**（复用既有维护调度），失败 15:40 重试一次；另支持手动 | 15:00 后日线已闭合 | `as_of=当日`，覆盖写 |
| 30m | 每根闭合后 **+2 分钟**：10:02 / 10:32 / 11:02 / 11:32 / 13:32 / 14:02 / 14:32 / 15:02 | 只用已闭合 bar；`bar_closed_at` 记录闭合时刻 | `effective_from = 下一根 bar`（如 10:00 bar → 10:30 bar 生效），前端明确标注 |

30m 行业全量（128 只）；30m 个股仅在日线「由空转多」行业内计算（≤20 个行业），其余显示「未计算」而非 0。收盘后 15:02 那次同时刷新日线依赖的 `m_enh` 序列。

## 4. 与现有门控 / 股票池的关系

- **门控**：共用 `compute_rating_frame`；看板只**读**门控状态（`fetch_gate_status`），不写 `market_gate` 相关配置/快照。统一 ENH 是对门控代码本身的口径修正（§12 M1），不新增开关。
- **股票池**：看板不读写 `stock_pools` / `stock_pool_*`；成分股来自 TDX 行业成分，仅用于展示。不建立跨表外键，避免耦合。
- **策略/风控**：无任何调用；看板服务不 import 交易/实盘模块。

## 6. 性能预算

| 项 | 规模 | 预算 | 手段 |
|---|---|---|---|
| 日线行业 | 128 × 320 根 | ≤ 90s | 8 线程并发取数；单只计算 <30ms |
| 日线个股 | 约 4–5k × 320 根 | 首轮 ≤ 15min（一次性回填）；日常 ≤ 8min | 跳过停牌/无新 bar；8 线程；只写当日快照 |
| 30m 行业 | 128 × 320 根 × 8 次/日 | ≤ 60s/次 | 同上 |
| 30m 个股 | ≤20 行业 × ~50 只 | ≤ 45s/次 | 仅「由空转多」行业 |
| API 列表 | ≤ 200 行（行业）/ ≤ 500 行（个股） | p95 < 300ms | 联合索引 + 快照表直查 |
| 汇总接口 | 单日聚合 | p95 < 500ms | 60s 进程缓存 |

SQLite 写并发：批次写走单事务、`MAINTENANCE_GATE` 不介入（只读看板，不与备份/增量回测抢闸），但写入限流为每 200 行一次 commit，避免长事务。

## 7. 分阶段交付与验收

- **阶段 1（本文件）**：方案评审通过即进入阶段 2。
- **阶段 2（后端与数据）**：迁移 → `rating_core` → `board_service` → API；验收：真实数据跑通 128 行业日线快照 + 一只行业成分股样例 + 30m 一次；给出样例 JSON 与耗时。
- **阶段 3（前端）**：路由/侧栏、看板页、备选股池卡移除；验收：页面可打开，给出入口 URL 与截图路径。
- 提交：每阶段单独 commit + push；推送失败如实说明，不阻塞本地交付。

## 8. 风险与未确认

- TQ 30m 历史深度与当日盘中可用性（现有 `snapshot_bars.py` 说明盘中 1m 只到上一交易日，30m 依赖客户端 `get_market_data`）；阶段 2 先实测一次 30m 取数，不足则退化为「日线 + 盘中快照聚合」。
- 成分股总量与重复归属（一只股票可属多个行业）——按 `(industry_code, stock_code)` 存，不做去重合并。
- 128 名单可能随通达信更新增删；以 `board_industries` 快照为准，页面显示名单校验结果。
- 个股日线含除权跳变：统一 `dividend_type="front"`；指数不复权。
