## 0. 对四点质疑的回应（先给结论）

| 质疑 | 本版结论 |
|---|---|
| 额度不是常量 | 额度改为由 `max_positions / max_holdings / single_open_ratio / max_order_amount / max_single_position_pct / max_order_pct_equity / target_utilization / equity_cap` 动态推导；500 万只是 #4 当前配置的计算结果。给出推导式、字段来源、缺失降级表。 |
| 腾挪额度归属要有标准 | 定义五类归属：策略内、组合内、会话内、现金管理、用户自定义。默认 `组合内`（且总开关关闭时不外借），跨组合/自定义必须显式开启；每笔出借生成 `LoanLot` 账本，界面逐笔显示「归谁、借给谁、何时到期、何时召回」。 |
| 没有单仓上限怎么判定 | 只有数量上限、没有金额上限时，用历史利用率的分位数/回撤期最坏值/5 日利用率跃升分位数做保守预留；**不用均值**。给出「不足则预留、富余才外借」的判定式、样本不足降级、以及 #14 的反例计算。 |
| 门控资金释放 | 以 `MarketGateTracker` 的右移一日状态为源，设计 `OPEN / CLOSED / REOPENING / UNKNOWN` 状态机；关闭后延迟 1 个交易日释放、恢复时先召回、延迟期内 `pending_release` 不可借、召回期 `pending_recall` 不计入可借池，避免两边同时占用。回测与实盘分开写口径。 |

一句话：**0018 的「500 万额度」是案例，不是规则；本版把它改成「由配置算出来的授权上限」，并把「借出/归还」做成有账本、有期限、有优先级的流程。**

## 1. 额度推导模型：从配置算出来，不是常量

### 1.1 符号与字段来源

| 符号 | 含义 | 字段 / 来源 | 缺失时 |
|---|---|---|---|
| `E_p` | 组合当前权益 | `cash + 持仓市值`，逐 bar 更新 | 必有 |
| `G_p` | 组合当前毛敞口 | `持仓市值 + 在途买入承诺` | 必有 |
| `cap_p` | 组合权益上限 | `portfolio_strategies.equity_cap` | 无上限 |
| `T_p` | 目标仓位上限 | `portfolio_strategies.target_utilization`（新增，默认 0.95） | 0.95 |
| `H_p` | 组合持仓数量上限 | `portfolio_strategies.max_holdings`（默认 10） | 10 |
| `S_j` | 策略持仓数量上限 | `strategies.max_positions` | 回退 `H_p`；再缺回退 1 |
| `r_j` | 单仓开仓比例 | `strategies.single_open_ratio` | 回退 `1 / S_j` |
| `A_j` | 单笔绝对上限 | `strategies.max_order_amount` | 视为无绝对上限 |
| `P_j` | 单笔权益比例上限 | `strategies.max_order_pct_equity`（新增，默认 0.03） | 视为无此约束 |
| `C_p` | 单票集中度上限 | `portfolio_strategies.max_single_position_pct × E_p` | 视为无此约束 |
| `Q_j(code)` | 容量上限 | 层 1 `CapacityBudget` 的 `bar/day/5d` 最小可用量 × 价格 | 必有 |
| `Rd_j` | 风险因子 | 见 1.6（回撤/日亏/熔断） | 1.0（无风控配置时） |
| `capital_ratio_j` | 策略资本占比 | `strategies.capital_ratio` | 等分 `1 / 策略数`，并标记降级 |

### 1.2 单策略可部署额度

```text
策略资金 F_j = capital_ratio_j × min(E_p, cap_p)

单仓配置上限 U_j = min(
    r_j × F_j,                    # 目标单仓
    A_j           若存在,
    P_j × E_p     若存在,
    C_p           若存在    # 组合级单票上限，执行时按 code 合计校验
)

策略毛额度 Gross_j = S_j × U_j
策略授权 Entitlement_j = Gross_j × Rd_j
```

执行时再叠加逐票容量：

```text
单票可执行上限 U_j(code) = min(U_j, Q_j(code) × 当前价格)
```

关键点：

- `A_j` 只作为**其中一项**，不再是唯一决定项；`A_j` 缺失时也天然有上限，因为 `r_j × F_j` 是有限的。
- 如果 `A_j` 存在但很大，`P_j × E_p`、`C_p`、`Q_j(code)` 会把它继续压住，避免「取消 50 万后就无限买」。
- 容量逐票计算，不能用统一金额替代。

### 1.3 组合可部署额度

```text
组合理论毛敞口 Gross_p = min(
    Σ_j Gross_j,
    H_p × max_j(U_j)             若 H_p 存在,
    T_p × E_p,
    cap_p                        若存在
)

组合授权 Entitlement_p = Gross_p × Rd_p

组合当前缺口 Headroom_p = max(0, Entitlement_p − G_p)

组合本次需要现金 OwnNeed_p = min(Headroom_p, 可执行机会金额)
```

`可执行机会金额`：

```text
Opportunity_p = Σ_j min(
    slot_gap_j,
    signal_count_j
) × U_j
```

其中 `slot_gap_j = max(0, S_j − 当前持仓数_j)`，`signal_count_j` 为上一交易日及更早的未执行信号数 + 最近 N 日平均新信号数（N 默认 5，只用完整历史日）。

### 1.4 会话可分配池

```text
组合保护现金 Protect_p = OwnNeed_p + 现金下限_p + 在途买入承诺_p
其中 现金下限_p = min_cash_reserve_pct_p × E_p    （默认 0.03）

组合可外借 Lendable_p = max(0, cash_p − Protect_p)

会话可分配池 PoolFree = max(0, Σ_p Lendable_p − 会话现金下限)
会话现金下限 = pool_cash_floor_pct × Σ_p E_p      （默认 0.03）
```

注意：`Lendable_p` 是「本组合今天确定用不到、且不会被自己明天突然需要」的钱；它必须同时满足 1.5 的无上限保守预留规则。

### 1.5 #4 的额度是算出来的（示例，不是常量）

#4 当前配置：`E=3,888 万`、`cap=无`、`S=10`、`r=10%`、`A=50 万`、`T=95%`。

```text
F = 1 × 3,888 万 = 3,888 万
U = min(10% × 3,888 万 = 388.8 万, 50 万) = 50 万
Gross = 10 × 50 万 = 500 万
Entitlement = 500 万
利用率上限 = 500 / 3,888 = 12.9%
```

如果配置变化：

| 配置 | 单仓上限 `U` | 毛额度 `Gross` | 利用率上限 |
|---|---:|---:|---:|
| 10 槽 × 50 万（#4 现状） | 50 万 | 500 万 | 12.9% |
| 20 槽 × 50 万 | 50 万 | 1,000 万 | 25.7% |
| 20 槽 × 3% 权益 | 116.6 万 | 2,333 万 | 60.0% |
| 20 槽 × 5% 权益 | 194.4 万 | 3,888 万 | 100%（受 `T=95%` 压到 95%） |

所以文档里不应该出现「额度 = 500 万」这种规则；正确表述是**「额度 = 上述公式在当前配置下的结果」**。配置改了，额度自动变。

### 1.6 风险因子（额度上限，不是事后告警）

```text
dd_p = 1 − E_p / peak_p
dd_factor = clamp((max_drawdown_p − dd_p) / (0.5 × max_drawdown_p), 0, 1)

day_loss_p = max(0, −当日盈亏_p) / daily_loss_base_p
daily_factor = clamp((daily_loss_limit_p − day_loss_p) / (0.5 × daily_loss_limit_p), 0, 1)

breaker_factor = 0 若组合/会话熔断、日亏暂停，否则 1

Rd_p = min(dd_factor, daily_factor, breaker_factor)
Rd_j = min(Rd_p, 策略级风控因子)
```

- 回撤达到上限一半之前不收紧；达到上限时新开仓额度为 0。
- 日亏同理；熔断直接 0。
- 风控因子只压额度，不强制卖出。

### 1.7 缺失字段降级表（必须显式标记 `degraded`）

| 缺失项 | 降级规则 | 风险 |
|---|---|---|
| `max_order_amount` 缺失 | 用 `single_open_ratio × F`；仍无则用 `F / S` | 单笔可能偏大，必须靠 `max_single_position_pct` / 容量兜底 |
| `max_single_position_pct` 缺失 | 进入第 3 节「无单仓上限」历史利用率模式 | 预留不足会在行情中被迫召回 |
| `max_positions` 缺失 | 用组合 `max_holdings`；再缺用 1 | 额度可能被低估 |
| `max_holdings` 缺失 | 用策略 `max_positions` 之和；再缺用 10 | 组合级集中度可能偏高 |
| `single_open_ratio` 缺失 | `1 / S_j` | 等价等权分槽，非最优但不至于超配 |
| `target_utilization` 缺失 | 0.95 | 若历史最高利用率 > 95%，仍不外借超过 95% |
| `equity_cap` 缺失 | 不设权益上限 | 靠 `T_p` 和单票集中度约束 |
| `capital_ratio` 缺失/合计≠1 | 等分并归一；标记 `capital_ratio_degraded` | 与用户预期份额不一致 |
| `min_cash_reserve_pct` 缺失 | 0.03 | 现金缓冲偏薄 |
| 历史样本 < 60 日 | 不允许外借，`Protect_p = cash_p` | 资金利用率暂时不提升，但不会抢钱 |
| 门控状态未知 | 不允许释放，`pending_release` 不生成 | 保持保守 |

原则：**任何缺失都只能让额度更保守，不能推出「无上限」或「可以随便借」。**

## 2. 腾挪额度的归属：这笔钱归谁、借给谁

### 2.1 资金状态机

每一块钱在同一时刻只能处于一个状态：

```text
IDLE              自有、未占用
PROTECTED         自有、预留给本策略/本组合今天的机会或现金下限
PENDING_RELEASE   已判定闲置，等待释放延迟结束（不可借）
LENDABLE          可出借
LENT              已借出（有 LoanLot）
PENDING_RECALL    已发起召回，借款人额度已冻结，等现金回流
RETURNED          已归还，回到 IDLE/PROTECTED
```

状态迁移必须由计划任务或成交事件驱动，禁止在查询时临时推断。

### 2.2 五类归属策略（可选项）

| 策略 | 谁可以使用 | 适用条件 | 默认 | 主要风险 |
|---|---|---|---|---|
| `strategy_only` | 仅本策略 | 单策略、或策略间信号高度相关、或用户不接受跨策略 | **总开关关闭时默认** | 利用率最低，但最可控 |
| `portfolio` | 同组合其他策略 | 同组合多策略、主从、策略间低相关 | **总开关开启时默认** | 同组合策略可能同时爆发，需保留组合级预留 |
| `session` | 同会话其他组合 | 多组合共用同一真实账户、股票池不重叠或可归因 | **必须显式开启** | 跨组合同票、账实归因、真实额度切分 |
| `cash_management` | 现金出口（逆回购/货基/现金理财） | 有真实可执行、可验证回流的通道 | **默认关闭且当前不可用** | 它不是策略，不能用回测资格卡；判据见 0020 §13（C1–C8），现有 `cash_enhance` 只记事件、不下单 |
| `custom_pairs` | 用户指定的 A→B 配对 | 用户明确知道两边策略逻辑与风险 | **默认关闭，需显式勾选并确认免责声明** | 配对错误、单边行情、责任在用户 |

补充：

- **默认行为**：`capital_pool_enabled=false` → 一切 `strategy_only`，不外借；开启后 `pool_scope=portfolio`，只做组合内；跨组合必须把会话配置为 `pool_scope=session`。
- **现金管理选项目前必须显示为「未实现」**：底层 `cash_enhance` 只记决策事件，不能下单、不能申购、不能划转。它不是「固收类策略」，而是现金出口（`borrower_type=cash_outlet`），不适用回测资格；实现路径与 C1–C8 判据见 0020 §13。等真正接入通道并验证回流后再开放。
- **自定义配对**：每对配置 `lender → borrower`、最大出借比例、最长期限、是否允许强召回；默认 1 天到期、不允许强平；界面需二次确认。

### 2.3 LoanLot：每笔出借都有账本

```python
@dataclass
class LoanLot:
    loan_id: str
    lender_type: str          # strategy / portfolio / session
    lender_id: int
    borrower_type: str        # strategy / portfolio / cash_outlet
    borrower_id: int
    scope: str                # portfolio / session / custom
    principal: Decimal
    outstanding: Decimal
    created_at: datetime
    due_at: datetime          # 默认 T+1
    recall_requested_at: datetime | None
    recall_deadline: datetime | None
    status: str               # active / recall_pending / returned / written_off
    reason: str               # demand_idle / gate_closed / manual / custom
```

硬约束：

```text
(1) 每笔 principal > 0；同一时刻同一笔钱只能在一个 LoanLot 里
(2) Σ lender.outstanding = Σ borrower.received（按 scope 汇总）
(3) 任何时点 Σ LENT + Σ LENDABLE + Σ PROTECTED + Σ PENDING_RELEASE
    + Σ PENDING_RECALL + Σ 现金下限 = Σ cash（按 scope 汇总）
(4) 不允许 rehypothecation：借入方不得把借来的额度再借出（v1 硬限制）
(5) 到期末归还；未归还进入 recall_pending，借款人新买入被阻断
```

### 2.4 借给谁：排序规则

> 本节只定义「在已合格的借款人之间如何排序」。**谁有资格成为借款人、最多几个、两个借款人能不能搭配**，见 [0020 §1–§3](file:///d:/project/tq-iquant-web/docs/plans/0020-借款方资格与搭配验证.md)；现金出口类借款方不适用回测资格，见 0020 §13.2 的 C1–C8。下面的过滤条件只是资格判据的必要子集，不能替代 0020 的 E1–E12、C1–C8 与硬约束 H1–H8。

只有同时满足以下条件的借款人才能进入候选：

```text
- 在允许的 scope 内（同组合 / 同会话 / 自定义配对）
- 门控状态为 OPEN（或该策略 market_gate_mode=off）
- 仍有空槽位（slot_gap > 0）
- 风险因子 > 0
- 没有未完成的召回
- 额度缺口 > 最小出借单位
```

候选排序分：

```text
score_b = demand_ratio_b × risk_factor_b × priority_weight_b
```

- `demand_ratio` = 借款人需求 / 其理论最大毛额度，避免大组合永远优先。
- `priority_weight` 来自 `priority`；主从场景下 master 权重高于 slave。
- 同分时按 `(priority desc, strategy_id)` 兜底，保证确定性。
- 同一 `code` 有多个借款人时，先按第 4.4 节的同票配额分配，再落到 LoanLot。

### 2.5 界面如何表达「当前这笔闲钱归谁」

- **组合/策略列表**新增列「闲钱归属」：
  - 灰色 `PROTECTED`：本策略预留，不可借；
  - 蓝色 `IDLE/LENDABLE`：归本策略，可借出；
  - 橙色 `LENT`：已借给 `组合 B / 策略 B2`，到期 `T+1 14:50`；
  - 红色 `PENDING_RECALL`：已召回，借款人停止新买入，等待回流；
  - 黄色 `PENDING_RELEASE`：门控关闭后等待释放，暂不可借。
- **悬停明细**：展示 `loan_id`、本金、出借人、借款人、创建时间、到期时间、召回截止、状态。
- **每日资金归属表**：可导出 CSV，按「组合 → 策略 → 状态 → 金额」列出，日终与现金对账一致。
- **显式选择**：切换到 `session` 或 `custom_pairs` 时弹确认框，写明「跨组合资金会被重新归属、历史组合收益不可直接比较、由用户承担判断责任」。

## 3. 没有单仓金额上限时：用历史利用率保守预留

### 3.1 进入条件

同时满足：

```text
max_order_amount 为空
且 max_single_position_pct 为空
且 max_order_pct_equity 未显式配置
```

如果只有 `max_order_amount` 为空、但 `max_single_position_pct` 存在，则直接用 `max_single_position_pct × E_p`，不进入本节。

### 3.2 数据口径

- 数据源：组合/策略日快照（`backtest_daily_snapshots` / `live_portfolio_daily`；策略级无独立快照时用「组合利用率 × 策略资金占比」作代理，标记 `proxy`）。
- 窗口：最近 `N=252` 个交易日；不足 252 用全部可用。
- 剔除：
  - 策略启动后前 20 个交易日；
  - 权益单日跳变 > 20% 的异常日（增资/撤资/数据错误）；
  - 门控关闭日（除非用户选择「含门控关闭日」的保守口径，见 3.5）。
- 计算：

```text
u_t = market_value_t / total_value_t
u_p50 / u_p90 / u_p95 / u_max
u_dd_worst = 组合回撤 > 3% 的交易日中的最大 u_t
Δu_p95_5d = 5 日利用率增量的 95% 分位
n = 有效样本数
```

### 3.3 预留规则（默认 p95 口径）

```text
u_reserve = min(
    target_utilization_p,
    max(
        u_p95,
        u_dd_worst,
        u_current + Δu_p95_5d
    )
)
```

解释：

- `u_p95`：覆盖 95% 的历史交易日；
- `u_dd_worst`：覆盖回撤期的最坏占用，避免在最难受的时候召回；
- `u_current + Δu_p95_5d`：覆盖「行情突然来、5 天内利用率快速冲高」的情形；
- 三者取最大，再受目标利用率封顶。

然后换算成现金预留：

```text
OwnNeedCash_p = max(0, u_reserve × E_p − G_p)
Protect_p = OwnNeedCash_p + 现金下限_p + 在途买入承诺_p
Lendable_p = max(0, cash_p − Protect_p)
```

判定规则：

```text
若 Lendable_p < max(最小出借单位, 5% × cash_p)：不外借（不足则预留）
若 Lendable_p ≥ 上述阈值：才允许登记 LoanLot（富余才外借）
```

### 3.4 为什么不能按平均值预留

以 #14（无单笔上限）为例：

- 全期平均利用率 **54.35%**；
- 2017 年 **72.7%**、2018 年 **59.6%**、2020 年 **58.2%**、2024 年 **47.5%**；
- 均值把「平时的低占用」和「行情中的高占用」混在一起。若按 54.35% 预留，遇到 2017 年那种 72.7% 的行情，需要额外 18.4 个百分点的现金。

假设权益 1,000 万，18.4% 就是 **184 万**。如果这 184 万已经借给别的策略，只有两条路：

1. 召回 → 借款人被迫卖出或停止买入，通常发生在行情最好、最不该卖的时候；
2. 不召回 → 原策略买不满，利用率看似提高，实际收益被转移且风险归因失真。

所以无上限场景必须用**分位数 + 回撤期最坏值 + 跃升速度**做上限，而不是均值。

### 3.5 可选的保守等级

| 口径 | `u_reserve` | 适用 | 代价 |
|---|---|---|---|
| `p90` | p90 + 跃升修正 | 追求利用率、能接受偶尔召回 | 召回概率较高 |
| `p95`（默认） | p95 + 回撤最坏 + 跃升修正 | 大多数情况 | 预留较多 |
| `max` | `u_max`（含泡沫期最高） | 绝不允许召回、资金体量大 | 几乎不外借 |
| `manual` | 用户指定固定比例 | 有明确风险预算 | 配置错误风险由用户承担 |

补充：

- 样本 60–250 日：在 `u_p95` 上加 0.05 安全边际（或使用 bootstrap 95% 置信上界）。
- 样本 < 60 日：`u_reserve = target_utilization`（默认 0.95），基本不外借，标记 `no_history`。
- 连续 2 日 `Lendable < 0` 才触发召回，避免单日抖动造成来回借还。

### 3.6 「不足则预留、富余才外借」的完整判定

```text
if 无历史 or 门控未知:
    Lendable = 0
elif cash − 现金下限 − 在途 < OwnNeedCash:
    Lendable = 0
else:
    Lendable = cash − 现金下限 − 在途 − OwnNeedCash
    if Lendable < max(一手市值, 5% × cash):
        Lendable = 0
```

## 4. 门控策略的资金释放与回收

### 4.1 门控状态来源

现有实现：

- `MarketGateTracker`：状态 `-1` 空头、`0` 中性、`1/2` 多头；`blocks(d) = state == -1`；`state_for(d)` 取**严格早于 d** 的最近状态日（右移一日，无前视）。
- 策略级 `market_gate_mode`：
  - `inherit`（默认）：跟随组合门控；
  - `off`：本策略不受门控；
  - `on`：组合未启用门控也强制使用基准门控。
- 门控只禁止**开仓/加仓**，不强平持仓；`bear_reduce_ratio` 可产生减仓信号。

定义策略级门控状态：

```text
gate_state(j, d):
    mode = ctx.market_gate_mode
    if mode == off:      return OPEN
    tracker = portfolio.current_market_gate
    if tracker is None:
        if mode == inherit and 组合门控未启用: return OPEN
        return UNKNOWN
    if mode == on or 组合门控启用:
        return CLOSED if tracker.blocks(d) else OPEN
    return OPEN
```

**UNKNOWN 的处理**：交易上保持现有 fail-open（查询异常放行），但**资金上不释放**——因为无法确认它是真关闭还是数据故障。

### 4.2 状态机

```text
GATE_OPEN  ──关闭确认──▶  GATE_CLOSED
GATE_CLOSED ──开放确认──▶ GATE_REOPENING ──资金归还完成──▶ GATE_OPEN
GATE_OPEN / GATE_CLOSED ──状态未知──▶ GATE_UNKNOWN（不释放、不新增出借）
```

时间线（`release_delay_days=1`、`recall_notice_days=1`）：

| 时点 | 事件 | 资金动作 |
|---|---|---|
| T 收盘 | 基准转空（state=-1） | 无（右移，T+1 才可见） |
| T+1 首 bar | 计划识别 `GATE_CLOSED` | 该策略新开仓额度=0；闲置额度进入 `PENDING_RELEASE`，**不可借** |
| T+2 首 bar | 释放延迟结束 | `PENDING_RELEASE → LENDABLE`，可登记 LoanLot |
| T+2 之后 | 借给同组合/同会话候选 | `LENDABLE → LENT` |
| T+10 收盘 | 基准转多（state=1） | 无（右移） |
| T+11 首 bar | `GATE_REOPENING` | 立即召回所有 `lender=该策略` 的 LoanLot；借款人额度冻结、停止新买入 |
| T+11 ~ T+12 | 借款人用自有卖出/空闲现金归还 | `PENDING_RECALL → RETURNED`；原策略优先拿回，`reopen_reserve` 不得被其他人借走 |
| T+12 仍未归还 | `recall_shortfall` | 原策略额度不足部分按未满足需求记录；默认不强平借款人，只停止其新买入 |

抖动保护：

- `release_confirm_days=1`：门控关闭连续 1 个交易日确认后才进入 `PENDING_RELEASE`。
- `reopen_confirm_days=1`：门控恢复连续 1 个交易日确认后才发起召回。
- 若在 `gate_hysteresis_days=2` 内来回切换，保持上一次状态，不重复借还。

### 4.3 释放规则（只释放真闲置）

```text
策略可释放 = min(
    该策略当前未使用的授权额度,
    cash − 该策略现金下限 − 该策略在途买入承诺
)
```

- 只释放「额度」，不释放持仓。
- 若门控关闭期间产生减仓，卖出回款先进入 `PROTECTED`，释放延迟结束才变 `LENDABLE`。
- 主从场景：
  - master 门控关闭、slave `inherit` → 两者都关闭，额度都可释放；
  - slave `off` 但 master 关闭 → slave 因为 master 不会开新仓而无法开仓，其实际需求为 0；按实际需求释放，不按假设。
- 不得把「预计会卖出」的钱提前借出；只借已到账现金。

### 4.4 召回规则（保证原策略优先拿回）

触发条件（任一）：

1. 门控恢复（`GATE_REOPENING`）；
2. 原策略/组合风险因子下降，需要提高预留；
3. LoanLot 到期（默认 T+1，可续期至 `loan_max_days=5`）；
4. 用户手动召回；
5. 原策略出现新的可执行机会，`OwnNeedCash` 上升。

动作顺序：

```text
1. 将 LoanLot 标记 recall_pending，设置 recall_deadline（默认 1 个交易日首 bar）
2. 借款人可用额度立即减去召回金额（防止继续下单）
3. 取消借款人未成交买单（recall_cancel_open_orders=true 时）
4. 借款人用空闲现金/卖出回款归还；默认不强制卖出（hard_recall=false）
5. 归还后 LoanLot 关闭，资金回到原策略 PROTECTED
6. 未按时归还：记 recall_shortfall，借款人新买入持续冻结，直到归还或用户手动强平
```

优先级：

- 原出借策略的 `reopen_reserve` 在池内**最高优先级**，召回资金不得再借给其他人。
- 同一策略多个借款人时，按 `due_at` 最早、金额最大、`loan_id` 排序依次召回。
- 现金管理/自定义配对同样遵守召回优先级；自定义配对可在配置中设置 `recall_priority=low`，但风险由用户承担。

### 4.5 如何避免两边同时占用

四条硬规则：

1. `PENDING_RELEASE` 不计入 `LENDABLE`，释放延迟内谁都不能用；
2. `PENDING_RECALL` 不计入 `LENDABLE`，召回期间只能归还，不能再借出；
3. 召回一发出，借款人额度立即扣减，不等现金到账；
4. 禁止再出借（no rehypothecation），一笔钱最多一层借贷。

日终恒等式（按 scope）：

```text
Σ cash = Σ IDLE + Σ PROTECTED + Σ PENDING_RELEASE
       + Σ LENDABLE + Σ LENT + Σ PENDING_RECALL + Σ 现金下限
```

### 4.6 回测与实盘的口径差异

| 项目 | 回测 | 实盘 |
|---|---|---|
| 门控状态 | 历史指数计算 `MarketGateTracker`，右移一日 | 同一 tracker + 每日门控快照表；以昨日状态为准 |
| 检测时点 | 每日首 bar 生成计划 | 每日首 bar 生成计划（09:30 后） |
| 释放延迟 | 1 个交易日，确定性 | 1 个交易日；受真实成交/到账影响 |
| 现金归还 | 成交即回填，按 bar 收盘/下一 bar 开盘记账 | 以柜台成交回填和可用资金为准；卖出款当日可用于买入 |
| 召回执行 | 自动取消未成交买单，按下一 bar 归还 | 取消未成交买单可选；默认不强平；无券/冻结时进入 shortfall |
| 门控未知 | fail-open 交易、不释放 | 同左；另外告警 |
| 盘中变化 | 不处理（门控日频） | 不处理；仅日频计划 |
| 记录 | `backtest_decision_events` + 计划快照 | `capital_plans` / `capital_loan_lots` / 日终归属表 |

## 5. 总流程：该不该借、借给谁、什么时候还

```text
Step 0  日初对账：更新 cash / 持仓 / 在途买入承诺 / 未归还 LoanLot
Step 1  计算每个组合 E_p、G_p、Headroom_p、风险因子 Rd_p
Step 2  计算每个策略 Entitlement_j（第 1 节公式）
Step 3  判定门控：
         - CLOSED 且确认 → 该策略需求=0，闲置额度进入 PENDING_RELEASE
         - UNKNOWN → 不释放
Step 4  计算 OwnNeed：
         - 有单仓上限：OwnNeed = min(Headroom, Opportunity)
         - 无单仓上限：OwnNeed = max(0, u_reserve × E − G)   （第 3 节）
Step 5  计算 Lendable：
         Lendable = max(0, cash − OwnNeed − 现金下限 − 在途)
         小于阈值 → 0（不足则预留，富余才外借）
Step 6  汇总 PoolFree（扣会话现金下限、PENDING_RELEASE、PENDING_RECALL）
Step 7  选借款人：
         先过资格（0020 E1–E12 或 C1–C8）、数量上限（默认 1 / 上限 3）、搭配硬约束
         过滤 scope / gate OPEN / 空槽位 / 风险因子>0 / 无召回
         按 score = demand_ratio × risk_factor × priority 排序
Step 8  同票配额：
         先算 Q_code，再按 priority×demand 分给多个借款人；master 优先
Step 9  登记 LoanLot，生成额度计划；每个数字写 reason
Step 10 回收：
         到期 / 门控恢复 / 风险上升 / 手动 → recall
         冻结借款人额度，设 recall_deadline，优先归还出借人
Step 11 日终对账与归属表落库
```

对应三个问题：

1. **该不该借？** 只有 `Lendable > 阈值`、门控状态已知、历史样本足够（无上限场景）、且不属于 `PROTECTED` 的钱才借。
2. **借给谁？** 先按 [0020](file:///d:/project/tq-iquant-web/docs/plans/0020-借款方资格与搭配验证.md) 判定借款方是否「已完成回测、参数未变、搭配硬约束通过」，且活跃借款方不超过 3 个；再在允许的 scope 内，按「门控开、有空槽、有需求、风险因子>0」过滤，按 `demand_ratio × risk_factor × priority` 排序；同票先分容量配额；主从 master 优先。
3. **什么时候必须还？** LoanLot 到期（默认 T+1、最长 5 天）、门控恢复、出借人风险/需求上升、或用户手动召回；召回截止为 1 个交易日内，未归还需记 shortfall 并冻结借款人新买入。

## 6. 回测实现口径（无前视）

### 6.1 计划时点

- 每个交易日首根 bar 生成 `CapitalPlan`；当日有效。
- 需求估计使用「上一交易日及更早」的 N 个完整交易日；不得使用当日尚未发生的行情。
- 门控状态使用右移一日的状态；当日收盘状态只影响下一交易日。
- 单笔上限的 ADV 使用「上一交易日前 20 个完整交易日」的成交额均值；不得使用当日全天量。
- 容量使用当前 bar 截至当下的累计成交量（因果），不得使用未来 bar。

### 6.2 额度与容量的关系

```text
可下单量 = min(
    策略额度剩余可买金额 / 价格,
    层 1 容量允许量,
    现金允许量,
    单笔上限,
    整手约束
)
```

- 额度不够 → `capital_budget_shrink`；
- 容量不够 → `capacity`；
- 两者分开统计，避免把「没钱」和「没量」混为一谈。
- 额度不得绕过容量；容量缩量后的残量继续占用额度，直到成交或 TTL 作废。

### 6.3 门控释放的回测语义

- `T` 日收盘确认空头 → `T+1` 计划进入 `PENDING_RELEASE` → `T+2` 可借。
- 恢复同理：`T` 收盘确认多头 → `T+1` 计划召回 → 借款人 `T+1/T+2` 用现金归还。
- 回测中借款人的卖出按现有成交模型回填，现金当日可用；不得假设「瞬间归还」。
- `recall_shortfall` 必须如实记录；若某笔召回导致原策略错过信号，计入 `recall_opportunity_cost`。

### 6.4 版本与复现

`params_snapshot` 记录：

```json

    "version": "v2-dynamic-entitlement",
    "scope": "portfolio",
    "ownership_policy": "portfolio",
    "no_cap_reserve_policy": "p95",
    "no_cap_history_window": 252,
    "release_delay_days": 1,
    "recall_notice_days": 1,

  }

```

`fields_hash` 覆盖所有影响额度的配置；哈希变化时旧结果标记「口径不可比」。

## 7. 实盘实现口径与风险

### 7.1 额度不是现金划转

- 实盘仍保留每个组合的虚拟 `account.cash`；资金池只生成 `budget` 与 `LoanLot`，不直接把 A 的 cash 改成 B。
- 成交时同时扣「借款人额度」和「借款人现金」；出借人现金不动，只把「所有权」标记为 `LENT`。
- 这样做的原因：真实柜台只有一个资金账户，平台没有划转指令；虚拟划转会造成账实不一致和负现金。

### 7.2 在途与冻结

```text
可用额度 = min(
    借款人 budget − used − reserved,
    借款人 cash − 现金下限 − 本组合在途买入承诺,
    真实账户可用 × 动态份额 × 0.98,
    单票集中度剩余,
    容量剩余
)
```

- 未成交买单在提交时进入 `reserved`；成交转 `used`；撤单/拒单释放。
- 日初计划必须扣除 `open_buy_reserved`；`pool_free < 0` 时当日不外借。
- 成交回填前校验 `cash_after ≥ 0`；为负则记 `negative_cash_guard`，冻结该组合新买入并进入次日优先补足。

### 7.3 真实额度切分

- 默认 `real_quota_basis=initial_capital`（兼容旧行为）。
- 开启会话资金池时建议 `real_quota_basis=dynamic`：真实额度按 `budget_i / Σbudget` 切，而不是按启动时的 `initial_capital`。
- 若当日计划缺失，回退 `initial_capital` 并记 `real_quota_fallback`，不得静默按 1 处理。
- 动态切分后仍要满足 `Σ real_quota_i ≤ 真实可用 × 0.98`，不能因为权重重分放大总额。

### 7.4 分币舍入

```text
raw_i = total × w_i
cents_i = floor(raw_i × 100)
剩余分 = total_cents − Σ cents_i
按 (余数 desc, 权重 desc, id) 依次 +1 分
断言 Σ cents_i == total_cents
```

额度、LoanLot 本金、日终归属表都使用同一套舍入，并在落库时保存 `raw` 与 `rounded`。

### 7.5 对账恒等式（含借贷）

```text
(1) Σ portfolio.cash = 会话虚拟现金合计
(2) PoolFree = Σ cash − Σ PROTECTED − Σ PENDING_RELEASE
             − Σ PENDING_RECALL − Σ 现金下限 ≥ 0
(3) Σ budget ≤ PoolFree；每个策略 used + reserved ≤ budget
(4) Σ LoanLot.outstanding = Σ LoanLot.received（按 scope）
(5) 单个出借人 Σ outstanding ≤ 其历史 Lendable 之和
(6) 每笔成交后 cash_i ≥ 0
(7) Σ portfolio.total_value ≈ 真实账户.total_asset（容差 0.5%）
(8) Σ real_quota_i ≤ 真实可用 × 0.98
(9) 日终：cash_i(收盘) = cash_i(开盘) + 卖出净额 − 买入净额 − 费用 + 流水
(10) 同一 code 的会话级合计市值 ≤ session_code_concentration_pct × Σ E
```

失败处理：

- `(2)(3)(4)(6)` 失败 → 立即停止新买入，升级告警，人工介入；
- `(7)(8)` 失败 → 只告警但停止跨组合出借，直到恢复；
- `(9)` 失败 → 以成交流水重算，不以计划为准。

### 7.6 账实与归属风险

- 多个组合共用一个真实账户时，真实持仓是合并的：平台订单按 `order_ref/strategy_id/portfolio_id` 归因；外部/初始持仓按股票池归属，重叠时按 `(priority, 初始资金, id)` 兜底并告警。
- 同一 `code` 被多个组合持有时，会话级集中度按合计市值算，单组合仍各自受 `max_single_position_pct` 约束。
- 历史组合收益在开启 `session` 归属后不再与真实账户子账户一一对应，报表必须标注「含资金调拨」。
- 现金管理选项当前不可用，必须在 UI 上标注「未实现」，不能把闲钱记成已申购货基。

### 7.7 生效与重启

- 会话运行中修改 `pool_scope`、`ownership_policy`、`release_delay`、`recall_notice`、`no_cap_reserve_policy`：进入待生效队列，**下次启动生效**。
- 计划、LoanLot、归属表持久化；重启后若当日计划版本一致则恢复，不重置 `used/reserved`；版本不一致则重新生成计划，但不得抹掉已有借据。
- 建议先跑 `capital_pool_shadow=true`：只计算与落库，不参与下单；影子稳定后再强制执行。

### 推荐顺序

```text
A（额度推导）→ B（组合内借贷）→ C（无上限预留）
→ D（门控联动）→ E（会话级）→ F（实盘影子）→ G（实盘强制）
```

理由：额度和归属是地基；无上限预留决定「借多少安全」；门控决定「什么时候借/还」；跨组合和实盘最后做，避免在账实风险没解决前放大范围。

## 11. 明确不做的事

1. 不把「500 万」当规则；它只是 #4 当前配置的计算结果。
2. 不按历史平均利用率预留；无上限场景必须用分位数/最坏值/跃升速度。
3. 不做主从共享钱包；主从是信号门禁，资金用「master 优先预留」。
4. 不做跨会话资金池；不同会话对应不同真实账户。
5. 不默认强制卖出归还；召回以冻结新买入、等待现金回流为主。
6. 不把现金管理写成已可用；现有 `cash_enhance` 是占位，选项必须标注「未实现」。
7. 不允许 rehypothecation；一笔钱最多一层借贷。
8. 不为提高利用率放宽容量、费用、集中度或回撤约束。

## 12. 一页结论

- **额度 = 公式结果，不是常量**：`min(槽位 × 单仓上限, 目标利用率 × 权益, 权益上限, 容量)`；字段缺失只能更保守，不能变成无上限。
- **归属必须有账本**：默认同组合内借；跨组合/自定义必须显式开启；每笔钱有 `LoanLot`、到期日、召回截止，界面逐笔显示归谁。
- **无上限时按历史高位预留**：`u_reserve = max(p95, 回撤期最坏, 当前 + 5 日跃升 p95)`；不按均值；样本不足不外借。
- **门控关闭先延迟释放、恢复先召回**：关闭 T+1 确认、T+2 可借；恢复 T+1 召回、原策略优先拿回；释放期和召回期都不计入可借池，防止两边同时占用。
- **回测与实盘分开**：回测用右移门控、日频计划、无前视；实盘再加在途、真实额度、最大余数、对账恒等式和影子模式。
- **落地顺序**：额度推导 → 组合内借贷 → 无上限预留 → 门控联动 → 会话级 → 实盘影子 → 实盘强制。
