## 0. 执行硬约束

1. **默认路径零变化**：所有新能力挂在默认关闭的开关下（`capital_pool_enabled`、`pairing_enabled`、`loan_model_enabled`、`cash_outlet_enabled` 均为 `false`）。关闭时，回测结果、实盘行为、事件、快照、API 响应必须与现在逐位一致。
2. **只加不删**：数据库迁移只做「加表 / 加可空列 / 加索引」；不重命名、不回填、不改既有列语义。破坏性变更一律拆到后续版本。
3. **回测先于实盘**：任何额度/借贷/召回逻辑必须先在同源回测里跑通，才能进入实盘影子；影子期未通过不得进入强制。
4. **实盘只读优先**：F 阶段之前，任何新逻辑不得改变真实委托；F 阶段影子也不得改变委托。
5. **可解释**：每个额度、借据、召回、拒绝都要能落一条事件，包含 `version`、输入、输出、原因码。
6. **可回滚**：每个阶段都有独立开关与回滚步骤；迁移必须验证 `upgrade` 与 `downgrade`。
7. **不动 8001**：本计划实施期间不重启、不操作 8001 实盘；实盘验证在隔离会话/影子模式进行。

## 1. 实施总览

### 1.1 阶段出口

| 阶段 | 目标 | 阶段结束时用户能看到什么 | 能操作什么 |
|---|---|---|---|
| **A** | 额度推导器（纯函数 + 只读展示） | 回测详情/组合页出现「额度推导」只读卡片：资金上限、目标利用率、缺口 | 只能看，不能借、不能改行为 |
| **B** | 组合内归属 + LoanLot + L2 搭配 | 回测管理出现「+ 新建拼盘」（仅同组合、默认 1 个借款方）；评估卡、合并回测、L2 拼盘草稿 | 挑主、挑 1 个对象、评估、跑合并回测、保存草稿 |
| **C** | 无上限预留 + 容量曲线 + 现金出口判据 | 评估里出现历史利用率分位、预留额、容量斜率；现金出口候选与只读建议 | 查看建议；不能执行出口 |
| **D** | 门控释放/召回 | 评估里出现门控关闭重合、释放/召回时间轴 | 查看门控驱动的影响 |
| **E** | 会话级归属 + L3 拼盘 | 跨组合拼盘、最多 3 个借款方、运行组详情、基线对比、成员折叠 | 发起 L3 联合回测、生成/批准拼盘 |
| **F** | 实盘继承（影子） | 实盘会话可绑定拼盘；拼盘卡片；理论 vs 实盘按成员对比；影子健康 | 绑定/解绑、影子观察、通道小额验证 |
| **G** | 实盘强制 + 现金出口执行 | 健康看板、暂停/退役、召回记录、现金出口操作卡 | 强制借贷、手动召回、暂停/退役、出口人工/半自动/自动 |

### 1.2 关键路径（必须串行）

```text
A1 → A2 → A3 ─┬→ B1 → B2 → B3 → B6 → E2 → E3 → E4 → E5 → F1 → F2 → F3 → F4 → G1 → G2 → G3
              ├→ B4 → B5 ────────────────────────────────┘
              ├→ C1 → C2 → C3 ────────────────────────────┘
              └→ C4 → C5 ────────────────────────────────┘
D1 → D2 → D3（依赖 B2/B3）──────────────────────────────────┘
```

必须串行的原因：

- **A2 必须先于 B2/E1**：没有统一的额度推导，策略接入与会话池会各算一套。
- **B1 必须先于 B2/B3/E2**：LoanLot 是借贷记账的唯一真相，先有账本再接执行。
- **B3 必须先于 E2**：单组合回测都跑不通，不能直接做多组合。
- **B4 必须先于 B5**：资格不通过就不该进入评估。
- **C1 必须先于 C2/E1**：没有预留口径，可借额会是拍脑袋。
- **D2 必须先于 D3**：召回状态机没定，回测无法建模。
- **E2 必须先于 E3/E4**：运行组是 L3 的落库容器。
- **F1/F2 必须先于 F3**：绑定与继承没定，影子没有对照基准。
- **G1 必须先于 G2/G3**：强制借贷跑起来，对账与健康才有对象。

### 1.3 可并行的轨道

| 轨道 | 任务 | 可并行的前提 |
|---|---|---|
| 核心资金轨 | A → B → E → F → G | 串行主链 |
| 预留/C 轨 | C1 → C2 → C3 | A2 完成后即可与 B 并行 |
| 现金出口轨 | C4 → C5 | A1 完成后即可与 B 并行；C5 的回测接入依赖 B3 |
| 门控轨 | D1 → D2 → D3 | B2/B3 完成后可与 C/E 并行 |
| UI 轨 | B6 → C6 → E5 → F5 → G3 | 依赖对应 API 契约冻结；可先用 mock 做交互 |
| 回归轨 | B7 → E6 → E7 | 每个阶段结束前必须跑；B7 可与 B6 并行 |

并行纪律：

- 同一文件同一函数只允许一个任务改；跨任务改同一模块时先冻结接口（函数签名、事件字段、快照字段）。
- `portfolio.py` 的 `on_bar`、`live_engine.py` 的 `_dispatch_bar`、`backtest_engine.py` 的 `run_multi` 是高频冲突点，涉及它们的任务必须排期错开或由同一人串行完成。
