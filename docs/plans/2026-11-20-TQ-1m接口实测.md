## 2. 实测 A：`refresh_kline` 真实语义

调用：

```python
tq.initialize(__file__)
ret = tq.refresh_kline(stock_list=["600000.SH","688318.SH","000001.SZ","300750.SZ","920718.BJ"],
                       period="1m")
```

原始返回（逐字）：

```
{"ErrorId":"0","Msg":"refresh kline cache success.","run_id":"8"}
```

- 耗时 **0.010s**（5 只）/ 0.010s（30 只）；内部 `timeout_ms=600000`（600s），实际未触发超时——因为它是同步的缓存刷新命令，不等待下载。
- 调用前后 5 只样本的 `.lc1`：`size`、`mtime`、最后一根时间**全部相同**（2s 后复查）。
- 冷文件判别（最关键）：挑 6 个数据停在 2024–2025 年的 `.lc1`（如 `sh000006.lc1` 止于 2025-04-25 09:58），调用 `refresh_kline` 后等待 **10s / 20s / 60s**：

```
000006.SH -> 2025-04-25 09:58 (纯文件时间 04-25 09:58:01)  unchanged
000026.SH -> 2025-04-25 09:58                                   unchanged
000046.SH -> 2025-04-25 09:59                                   unchanged
000016.SZ -> 无 Close 字段（退市/无数据）
```

→ **`refresh_kline` 既不写文件、也不异步回补**；返回的 “success” 只代表“把客户端 K 线缓存标记为刷新”。

> 代码依据：[tqcenter.py](file:///D:/zd_zyb/PYPlugins/sys/tqcenter.py#L3016-L3056)（type=17、`timeout_ms=600000`、成功仅返回 Msg）。项目侧从未调用该接口（`main/` 下仅注释提及）。

## 5. 实测 D：分周期新鲜度（决定性证据）

同一时刻（00:40 左右）逐周期取 `count=2`：

```
600000.SH（沪，sh\fzline 未更新：0/26663）   1m→11-19 15:00   5m/15m/30m/1h→11-18 15:00   1d→11-19

000001.SH（沪指数）                          1m→11-19 15:00   5m/15m/30m/1h→11-18 15:00   1d→11-19
```

每个周期的最新时间**精确等于**该周期对应目录文件（`minline/*.lc1`、`fzline/*.lc5`、`lday/*.day`）的最后时间。

→ 这排除了“TQ 有自己的行情缓存/服务器补数”的可能：**TQ 就是本地文件读取器**。

## 6. 量纲与复权

### 6.1 量纲（可判定依据）

| 字段 | `.lc1` 文件 | TQ `get_market_data` | 依据 |
|---|---|---|---|
| Volume | 股 | **股** | 600000 15:00：`V=1,792,700`，×10.70 元 = 19,181,890 元 = 文件 amount |
| Amount | 元 | **万元** | 文件 19,181,890 → TQ 1918.19；`Amt/V = 1918.19/1792700 = 0.00107 万元/股 = 10.70 元` |
| 价格 | 元 | 元 | 三档复权下与 `.lc1` 尾值一致 |

交叉验证：688318 15:00 `Amt=252.92万 / V=42,700股 = 59.23 元 ≈ C=59.32`；300750 `10,491.83万 / 447,200 = 234.6 元 ≈ C=234.58`。

> 影响提示：项目 `_build_polars_kline` 把 `Amount` 直接转 Decimal 入 klines，未做 ×10000 换算；回测引擎本身不消费 Amount（`backtest_engine.py` 无引用），但若任何策略公式/指标读 klines 的 Amount，会得到“万元”口径而非“元”。

### 6.2 复权

- 1d 取 400 根，`none` vs `front` **315/400 根不同**，最早差异 2025-03-28，最晚 2026-07-15 → 复权确实生效。
- 1m 指定区间 2026-07-14～07-15（除权日）：720 根中 **480 根 none≠front**，例：`2026-07-14 09:31 none=9.12 → front=8.70`（比例 ≈1.048）。
- → **`dividend_type` 对 1m 同样生效**；回测按 `dividend_mode` 取前/后复权时，1m 与日线共用同一套复权逻辑。

## 7. 错误分类与前置条件

| 场景 | 原始返回/异常 | 分类 |
|---|---|---|
| 未 `initialize` | `RuntimeError: TQ数据接口初始化失败: 连接路径为空，请先调用 tq.initialize(path)` | 未初始化（不是“接口不存在”） |
| 非法周期 | `ValueError: 不支持15m,仅支持['1m', '5m', '1d']` | 参数不对（`refresh_kline` 只支持三档） |
| 代码无数据/退市 | 无异常；返回 dict 缺 `Close` 字段 | 返回空（非报错） |
| 数据陈旧 | 无异常；返回 `.lc1` 最后一根为止的数据 | 静默陈旧（最危险：调用方看不出“少了一天”） |
| 客户端未运行/未登录 | 本次**未制造**该场景（不允许停用户客户端） | 未验证 |

前置条件（本次已验证）：

- `tdxw.exe` 运行中时一切正常；项目注释与 `0008` 文档称需“已启动并登录行情”，**登录要求未单独验证**。

## 8. 能否作为实盘首选源

**已验证部分**
1. 接口可用、返回结构完整、性能足够（240 根 ×30 只 0.4s）。
2. 输出与回测所用 `.lc1` 同源同值 → 若盘中 `.lc1` 是实时的，则**与回测完全等价**（这正是用户想要的）。
3. `refresh_kline` 无法替代下载器，不能用来“拉当天数据”。

**未验证、必须盘中定**
1. 盘中 `.lc1` 是否被写入、写入频率、是否含“当前正在走的这一分钟”。
2. 若盘中不写文件，TQ 1m 是否另有内存合成通道（本次夜间观测不到；`0008` 文档曾实测盘中只到上一交易日 15:00，倾向“没有”，但需复测）。
3. 收盘后 00:15–00:25 那批写入是谁触发的（用户下载机制 / TDX 自身 / 00:15 重启的后端），以及它是否有盘中模式。

**额外事实**：即使 TQ 盘中 1m 可用，**当前实盘代码不会调用它**——tdx/ths/alert/goldminer 的 1m 由 `SnapshotBarSynthesizer` 快照合成，`live_service.py:1648-1671` 固定装配；改成“TQ 主 / 快照备”是代码改动，不是配置开关。

## 9. 明早盘中机械可执行清单

> 统一在 09:35 后开始（避开集合竞价），每步都给判据。样本沿用：600000.SH、688318.SH、000001.SZ、300750.SZ、920718.BJ。

### 9.1 TQ 1m 是否盘中前进（最关键）

```python
# 每 60s 执行一次，连续 10 次；同时记录墙钟与 .lc1 mtime
now = datetime.now()
df = tq.get_market_data(field_list=["Close","Volume"], stock_list=SAMPLES,
                        period="1m", count=3, dividend_type="none", fill_data=False)
print(now, {c: list(df["Close"][c].index)[-1] for c in SAMPLES})
```

判据：
- **PASS（可用）**：`last_bar_time` 随墙钟前进，且 `last_bar_time >= now - 2min`。
- **PARTIAL（可用但慢一根）**：`last_bar_time ≈ now - 1min`（只有已收线 bar）——可接受，但需记录。
- **FAIL（不可用）**：`last_bar_time` 停在 11-19 15:00 或不动。

### 9.2 `.lc1` 是否盘中写入

```
每 60s: Get-Item D:\zd_zyb\vipdoc\{sh,sz,bj}\minline\<code>.lc1 | Select LastWriteTime,Length
```

- **PASS**：盘中 mtime 前进（说明下载机制在工作）。
- **FAIL**：全天 mtime 不变（说明只有盘后 00:15 那批）。
- 同时用 9.1 判断：文件不动但 TQ 前进 → TQ 有内存通道（也是 PASS）；两者都不动 → FAIL。

### 9.3 是否含“未完成 bar”

在 10:00:20 调用 `count=3`，记录最后一根时间与当期 `.lc1` 末根：
- 若 TQ 最后一根 = 当前分钟（如 10:01），且 `.lc1` 无此根 → 内存合成“未完成 bar”，**时间戳=分钟终点**需人工确认边界语义。
- 若 TQ 最后一根 = 上一分钟（10:00）→ 只给已收线 bar，与回测口径一致（回测也是已完成 bar 收盘触发）。

### 9.4 `refresh_kline` 盘中是否有效

10:05 记录 5 只 `last_bar_time` → 调 `refresh_kline(...,'1m')` → 5s 后重取：
- **PASS**：last 前进；**FAIL**：不变（与本次夜间结论一致）。

### 9.5 与快照合成 bar 的偏差（同一分钟对照）

同一分钟内取 TQ 1m 与实盘 `SnapshotBarSynthesizer.completed_bars()` 的同标签 bar：
- 判据：`|Δclose|/close ≤ 0.05%`、`|Δvolume|/volume ≤ 1%`、OHLC 极值包含关系一致；不满足则记录偏差值（预期 TQ 更准，快照有采样误差）。

### 9.6 量纲复核

任取一根：`Amt/V` 应 ≈ `C/10000`（万元/股）。
- **PASS**：比值落在 `C/10000 × (0.99, 1.01)`；**FAIL**：差 10⁴ 倍（说明口径变了）。

### 9.7 采集记录表（每样本一行）

| 字段 | 值 |
|---|---|
| 墙钟 | |
| TQ last_bar_time | |
