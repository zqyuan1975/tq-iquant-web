# 0022 内置分钟数据下载（设计稿）

状态：待评审（本文件只做设计，不含实现承诺）
日期：2026-11-24
关联：`docs/plans/0021-资金池实施任务计划.md`、`main/core/services/kline_coverage_ledger.py`

## 1. 背景与已确认结论

- 外部工具 `D:\TDX数据工具v2.62` 走通达信 7709 主站协议直连，1m K 线按 32B 定长追加进
  `D:\zd_zyb\vipdoc\{sh,sz,bj}\minline\*.lc1`，无中间库。
- 平台侧 `tqcenter.get_market_data` 盘中只返回上一交易日 1m/5m，`refresh_cache` 只刷客户端
  内存缓存（`main/core/engine/live/snapshot_bars.py:1-8`、
  `main/core/engine/live/market_data.py:45-50`），因此**外部写 vipdoc 进不了引擎**。
- 结论：在平台内自研 7709 下载器，分钟数据落**平台自有存储**，实盘取数优先读自有存储，
  读不到再走现有回落链。不写 vipdoc，不依赖通达信客户端在前台。

## 2. 范围与非目标

范围内：
1. 只下「当前实盘会话所属组合 + 其备选股池」的标的，不做全市场。
2. 实盘会话启动即启动盘中循环下载，会话停止随之停止；无常驻后台全市场下载。
3. 增量 + 按日补缺 + 失败重试 + 限频；增量与缺日口径复用 K 线覆盖台账。
4. 分钟数据落平台自有存储；实盘读取新增优先层。

非目标：
- 不改回测侧取数（仍走 `TQData`/vipdoc），只在 §9 说明影响面。
- 不写 `vipdoc`，不改通达信客户端文件。
- 不改 `NativeMinuteDispatcher` 既有语义（不新增回落条件、不改停滞判定）。
- 不处理 `bar_time` 顺延单修复那条线。
- 不引入第三方行情客户端库，不复制外部工具任何代码/二进制/主站清单文件。

## 3. 代码清单从哪儿来

现状（只读核对）：
- 组合 → 池：`resolve_stock_codes(db, portfolio_strategy_id)`（`live_service.py:1265-1275`），
  按 `StockPoolStock.pool_id` 取启用标的。
- 会话 → 清单：`build_engine` 内聚合 `stock_codes`（`live_service.py:1642-1649`），PIT 模式
  并入历史成分股。
- 实盘持仓：来自券商回报/虚拟账本，启动时由 recover 建立，**不一定在池子里**。

设计：
- 清单在 `build_engine` 构造下载器时取一次（同一份 `stock_codes`，不另建口径）。
- 每轮循环开始前用「会话持仓 ∪ stock_codes」刷新，持仓集合从会话账本只读取快照；
  实现时以回调 `codes_provider()` 注入，避免下载器直接依赖账本内部结构。
- 清单为空 → 下载器空转并每小时告警一次，不抛异常影响会话启动。

## 4. 存储

选型：SQLite（与台账同技术栈，无新依赖，支持增量 upsert 与并发读）。

- 文件：`data/minute_store.sqlite3`（`work_dir` 同级，随应用根目录；WAL 模式）。
- 表：

```sql
CREATE TABLE IF NOT EXISTS minute_bars (
  code       TEXT NOT NULL,      -- 6 位数字，如 600000
  period     TEXT NOT NULL,      -- '1m'（本期仅 1m）
  bar_time   TEXT NOT NULL,      -- 'YYYY-MM-DD HH:MM'，bar 结束时刻（与 TDX 1m 一致）
  open REAL, high REAL, low REAL, close REAL,   -- 不复权原始价
  volume INTEGER,                -- 股（协议为手，落库 ×100）
  amount REAL,                   -- 元（服务端不给则 NULL）
  source     TEXT NOT NULL,      -- 'tdx7709'
  updated_at TEXT NOT NULL,
  PRIMARY KEY (code, period, bar_time)
) WITHOUT ROWID;
CREATE INDEX IF NOT EXISTS idx_minute_bars_code_time ON minute_bars(code, period, bar_time DESC);
CREATE TABLE IF NOT EXISTS minute_meta (k TEXT PRIMARY KEY, v TEXT);  -- schema_version 等
```

- 口径：`code` 6 位、不复权原始价、`volume` 单位股；与 `DEFAULT_DIVIDEND_TYPE="none"`
  （`main/core/tq/utils.py`）一致。
- 5m 一律由 1m 聚合（查询时聚合或物化视图），不单独下载，避免两套真值。
- 写入：`INSERT ... ON CONFLICT DO UPDATE`；单票单页一个事务，提交成功后才登记台账。

## 5. 模块落点

```
main/core/services/minute_download/
  __init__.py        # 对外：MinuteDownloadService.start()/stop()/status()
  protocol.py        # 7709 帧编解码：0x000D 两段握手 / 0x044E 心跳 / 0x052D K线（category=8 1m）
  hosts.py           # 主站池：配置优先，探活、延迟排序、失败隔离与切换
  store.py           # SQLite schema / upsert / 最新 bar / 按日区间读取
  downloader.py      # 计划(缺日)→拉取(分页)→写库→登记台账；限频、重试、线程生命周期
  store_source.py    # StoreFirstMinuteDispatcher：实盘优先读层，内含 inner dispatcher
```

协议实现要求：
- 只实现本期用到的三类报文，帧格式按公开协议独立编写；不 import 第三方库；
  不复制外部工具或 `eltdx` 的代码。
- `0x052D` 请求体 38B：`<HIHHHH6sHHHHIIH>` = 0x010C / 0x01016408 / 0x1C / 0x1C /
  0x052D / market(0/1/2) / 6 位 code / category(=8 为 1m) / 1 / start(<=65535) /
  count(<=800) / 0 / 0 / 0。
- 响应帧 16B 头 `<IIIHH>`：长度字段在 `[12:14]`（zip）与 `[14:16]`（unzip），
  两者相等时 body 为明文，否则 zlib 压缩。
- 1m 记录为**变长**：zipday(u16, `(year-2004)<<11 | month*100 | day`) +
  tminutes(u16) + O/C/H/L 四个前向差分变长整数（价格单位 0.001 元）+ vol(u32)
  + amount(u32)；vol 实测单位为**股**（amount/vol ≈ 价格），落库不再 ×100。
- 实测握手只做前两段（`0c021893…0d0001`、`0c021894…0d0002`）；第三段客户端信息
  会把连接切到另一模式，K 线请求只回 2 字节废帧。
- 解析按记录逐条校验（时间递增、价格非负），异常记录丢弃并计数，不整包失败。
- 单测用**自造帧 fixture**（构造合法响应字节 + 边界/畸形包），不依赖联网。

## 6. 接线点

### 6.1 覆盖台账（复用增量与缺日口径）
- 缺日计划：`plan_from_ledger(code, "1m", start, end, source="tdx7709")`。
- 写成功：`record_coverage(code, "1m", "close", [d, d], source="tdx7709")`，
  `source_path` 不传（无文件指纹语义）。
- 服务端确认当日无数据（停牌/未开盘）：`record_empty_days(...)`，避免每轮重复拉。
- 台账库沿用 `kline_coverage_ledger` 的默认路径与开关，不新建第二套台账。

### 6.2 实盘取数优先层
- 不改 `NativeMinuteDispatcher`。新增 `StoreFirstMinuteDispatcher(inner, store, frontier_max_lag=1)`：
  - `query_quotes_batch(codes, n)`：先查 store 最后 `n` 根；若最末 bar 标签 >= 期望最新闭合桶
    且与本轮 `now` 的滞后 <= `frontier_max_lag` 根 → 返回 store 结果（`bars_explicitly_completed=True`，
    与 native 同语义）；否则**原样委托 inner**（行为、日志、回落事件完全不变）。
  - `minute_health` 直接暴露 inner 的健康状态，避免两套健康口径打架。
- 装配点：`live_service.build_engine` 中包一层，开关 `live.minute_download.store_first=true` 才包；
  关闭即恢复原对象，零残留。

### 6.3 生命周期
- 启动：`start_session` 成功构造 engine 后启动下载线程（失败只告警，不阻断会话）。
- 停止：`stop_session` 同步 `stop()`（置停止事件 + join 超时 5s），未完成事务回滚。
- 会话异常崩溃：线程为 daemon 且带停止事件，进程退出不阻塞。

## 8. 失败与半写处理

- 半写：SQLite 事务原子提交；进程被杀最多丢当前页，不产生半根 bar。
- 失败：单票失败指数退避重试 `retry_times`；仍失败记入本轮失败清单并进入下一轮，
  不登记台账（下一轮自然重试）。
- 主站失败：单连接连续 3 次失败 → 隔离 60s 并切换下一主站；全部不可用 → 本轮跳过，
  按 5 分钟退避，不影响实盘主链路。
- 只读保护：`store.py` 只写自有库；对 vipdoc 全程无写操作。
- 数据校验：`bar_time` 必须落在交易日 09:31–15:00（含 11:30/13:00/15:00 边界），
  未来时间戳丢弃；同日重复 bar 以服务端后到为准。

## 9. 回测影响面（本期不动）

- 回测仍走 `TQData.get_history`（vipdoc）。自有存储与 vipdoc 在复权、停牌、集合竞价首根
  口径上需要一次对齐校准；未校准前不切，避免回测结果漂移。
- 后续切换的最小路径：新增 `MinuteBarProvider` 协议，`TQData` 侧按开关选择 store 实现，
  先 A/B 对照 N 个交易日再切默认。

## 10. 验证计划

1. 协议单测：自造帧 → 解析正确；畸形包/超长/乱序 → 丢弃并计数。
2. 存储单测：upsert 幂等、区间查询、5m 聚合、事务回滚。
3. 台账单测：首轮全缺、次日仅补当日、失败不登记、empty_days 去重。
4. 限频/重试单测：假 transport 计数，验证 ≤ 配置 QPS、退避次数。
5. 读层单测：store 新鲜→命中；store 落后→委托 inner；inner 异常→原样抛出。
6. 联网探针（人工执行一次、非 CI）：真实主站拉 1 只票当日 1m，与 vipdoc `.lc1`
   同段逐根对比时间与收盘价，记录差异；此步骤为上线前置门槛。
   **2026-11-24 已执行**：`115.238.56.198` / `124.71.187.122` 两段握手后返回真实
   1m（600000 10:31–10:40 连续、价格 10.66–10.68、vol/amount 与价格自洽），
   `MinuteDownloadService` 端到端 2 只票两轮共 8 请求、6400 根落临时库成功；
   未与 vipdoc 对照（本期不写 vipdoc，改以 amount/vol≈价格 与时间连续性自校验）。

## 11. 需用户拍板

1. **主站地址清单来源**：A 仅配置/环境变量（仓库不含 IP）；B 内置一份默认清单（可被配置覆盖）。
   建议 A（合规与可维护性更好），但首次配置需要人工填一份可达地址。
2. **首轮回溯天数**：15 个交易日（外部工具经验值）vs 30 日。建议 15，超出由服务端实际能力决定。
3. **是否同时落 5m**：建议只下 1m、5m 由 1m 聚合（单一真值）。
4. **读层命中判定**：落后 1 根即回落 inner（建议）vs 落后 2 根才回落。
5. **持仓票动态补下**：会话中途新增持仓是否下一轮即纳入（建议是，`codes_provider` 每轮刷新）。
6. **存储形态**：本期 SQLite（建议）vs 直接 parquet 分区（更适合回测，但增量写复杂）。
