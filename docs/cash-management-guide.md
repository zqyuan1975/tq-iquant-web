# 现金管理使用指南

> 面向使用「现金管理」页面的业务同事，不需要懂代码。界面上的按钮与提示以最新版本为准。

## 1. 现金管理是什么

把账户里暂时不用的现金，停放在**逆回购**、**场内货币基金 ETF** 这类低风险、能较快取回的品种上，赚一点利息，同时保证在真正要用钱的那天能拿回来。

它和策略交易是分开的两件事：

- 现金管理只登记「钱停在哪里、什么时候回来」，**不划转、不下单、不产生交易委托**；
- 它赚到的收益单独统计，**不进入策略归因**，不会影响策略业绩的计算；
- 每一笔投放与回流都记在页面下方的「台账」里，方便核对。

## 2. 在哪里登记标的

打开左侧导航 **交易 → 现金管理**（地址栏路径仍为 `/cash-outlets`，不影响使用）。

- 页面右上角有 **「登记标的」** 按钮；
- 如果列表还是空的，页面中间会有一行黄色提示，点其中的 **「点此登记」** 也能打开同一个窗口。

登记成功后：列表立即刷新，新标的会自动出现在下方「标的」下拉框中并选中，接着填金额就能「登记计划」。

## 3. 登记字段逐项说明

| 字段 | 怎么填 | 推荐取值 |
| --- | --- | --- |
| 代码 | 6 位数字。只支持：逆回购 `204xxx`（沪）、`1318xx`（深）；场内货基 `51xxxx`（沪）、`159xxx`（深） | 逆回购如 `204001`；货基如 `511880`、`511990` |
| 名称 | 可留空，留空时默认用代码 | 建议填简称，如「银华日利」 |
| 类型 | 「按代码自动识别」会按前缀判断：204/1318 记逆回购，51/159 记货基 ETF | 保持「按代码自动识别」即可 |
| 通道 | `manual` 只做人工登记，不走程序化下单；`tq`/`qmt`/`gj` 是程序化通道 | 只做人工选 `manual`；希望将来自动放行选实际使用的程序化通道 |
| 支持程序化下单 | 勾选表示该通道确实能自动下单。`manual` 下无法勾选 | 只有确认通道可程序化下单时才勾 |
| 流动性 | `T+0` 当日可用；`T+1` 次日可用；`期限` 到期回款 | 货基 ETF 常见 T+0/T+1；逆回购按期限 |
| 到期天数 | 仅「期限」需要填，1–7 天 | 按实际品种填 |
| 风险等级 | `R1` 最稳，`R2` 次之；选「未评」会被评估拦住 | 优先 `R1` |
| 回流确定性 | 本金回流时间有把握选「确定」；只能估计选「可能」 | 拿不准选「可能」，系统会提示不能当作确定额度 |
| 备注 | 可留空 | 写用途或联系人，方便日后对账 |

> 通道选择 `manual` 时，「支持程序化下单」会自动取消勾选；即使勾选，系统也会按人工通道登记。**manual 通道下 P3 不会自动放行。**

## 4. P1 / P2 / P3 三档差别

| 档位 | 界面名称 | 登记后会发生什么 | 适用场景 |
| --- | --- | --- | --- |
| P1 | P1 · 人工确认 | 进入「待确认」，有人确认后才算投放 | 刚开始用、金额需要逐笔把关 |
| P2 | P2 · 半自动 | 流程与 P1 相同，也要人工确认；差别在会话授权档位，绑定实盘会话时要求会话档位 ≥ P2 | 已有固定审批人、想减少授权摩擦 |
| P3 | P3 · 自动放行 | 满足全部条件时自动投放，否则自动转人工并列出原因 | 标的已验证、金额小额高频、对时效要求高 |

P3 自动放行需要同时满足：

1. 标的已完成 C8 小额实盘验证且在有效期内；
2. 通道已开启程序化下单（不能是 `manual`）；
3. 流动性为 `T+0`，或期限类且到期/结算不超过 7 天；
4. 结算与回流时间确定（「回流确定性 = 可能」不算）；
5. 已绑定一个 P3 档位的实盘会话。

任一条不满足，登记的计划会变成「待确认」，并在页面上列出不满足的原因。

## 5. 从「未验证」到「已验证」（C8）

登记只是把标的**配置**进系统，状态是「未验证」，不会被当成可借款的额度。判定一个标的是否可用，页面上的「评估」会做 8 项检查：

| 检查 | 在问什么 |
| --- | --- |
| C1 通道可下单 | 这个通道能不能自动下单 |
| C2 收益率数据 | 有没有可用的收益数据（历史太短会提示不可回测） |
| C3 流动性 | T+0 / T+1 / 到期是否在 7 天内 |
| C4 限额 | 金额是否满足最小、单笔、单日与递增要求 |
| C5 赎回 | 能不能提前赎回，或到期自动回款 |
| C6 风险等级 | 是否 R1/R2 |
| C7 回流确定性 | 预计可用日是否早于你的用钱日 |
| C8 通道验证 | 是否做过小额实盘验证、是否过期 |

**验证流程（C8）**：

1. 用最小金额真实做一笔申赎或逆回购，确认指令能成交、资金能按预期回款；
2. 把「验证金额、验证结果、验证日期」录入系统（当前由管理员在后台录入，页面暂未开放按钮），有效期默认 365 天；
3. 录入后 C8 才会通过，评估才可能返回「可用」；
4. 到期前需要重新做一次小额验证，否则会回到「未验证」。

## 6. 常见报错与处理

| 页面提示 | 原因 | 怎么办 |
| --- | --- | --- |
| 该标的已登记：xxxxxx | 代码已存在（409） | 不用重复登记，直接在下方「标的」下拉里选用 |
| 暂只支持逆回购（204xxx / 1318xx）与场内货基 ETF（51xxxx / 159xxx） | 代码前缀不在支持范围（422） | 换支持的品种；股票、债券等不能登记为现金管理标的 |
| 通达信未取到 xxxxxx.SH 的行情… | 代码错误、未上市或已退市（422） | 核对代码；确认行情软件里能看到该标的 |
| 通达信行情不可用（客户端可能未启动或未登录）… | 行情端离线（422） | 启动/登录通达信客户端后重试 |
| 登记接口暂不可用：新增路由需重启 Core 后才会加载… | 后端未加载新接口（404） | 请联系管理员重启 Core；前端已上线，不需要重新构建 |
| 现金管理开关未启用（`cash_outlet_enabled=false`） | 功能开关关闭 | 联系管理员打开开关后再使用 |

其它校验类提示（类型、通道、流动性、到期天数不合法）按提示改成允许值即可。

## 7. 放了钱之后怎么核对台账

页面下方的「台账」记录每一次投放：

- **状态**：待确认 → 已投放 → 已回流；另有已驳回、已取消；
- **预计回流 / 已回本金 / 收益 / 短款**：用来判断是否按期、足额回款；
- **回款**：登记实际本金与收益；如果实际本金少于计划，系统会要求填写短款原因；
- **台账对账**：只读校验，检查是否有逾期未回、是否有未说明的短款。提示「台账对账通过」即当前没有异常；否则会列出异常条目；
- 顶部汇总的「现金管理收益（单列）」只做展示，不进入策略归因。

建议节奏：每天或每次回款后点一次「台账对账」；出现短款务必填写原因，方便后续追溯。

## 8. 一句话流程

**登记标的（选代码 → 选通道与流动性 → 登记）→ 评估确认可用 → 登记计划（选 P1/P2/P3）→ 人工确认或自动投放 → 回款后登记并「台账对账」。**

记住两点：登记不等于验证；台账不划转、不下单，收益单独统计。
